# Highlighter 整套 UI 语言 · 高保真 HTML 原型 Spec

> 三版逻辑共用的唯一输入。只看本 spec，不参考其他版本。

## 产品是什么

**Highlighter** 是面向 Windows 的桌面截图与划词效率工具（Electron）。灵感早期来自 Snow Shot，现已是完整效率套件。

核心能力：
- 自由框选截图 / 延迟截图 / 全屏 / 焦点窗口 / 长截图
- 矩形椭圆箭头画笔高亮马赛克文字序号标注
- 本地 OCR 中英文、表格识别（TSV/CSV/Markdown）、二维码
- 区域录屏导出 MP4
- 桌面贴图、全屏画布
- 截图历史（缩略图、搜索、批量）
- 划词工具栏（复制/搜索/翻译/解释 + 自定义 AI）
- 独立翻译页、AI 多轮对话、多供应商模型配置
- Everything 本地搜索窗口
- 主题/主色/圆角/紧凑/皮肤/自定义 CSS、热键、托盘、数据目录

## 目标受众与场景

- **用户**：Windows 效率用户、开发者、内容创作者、学生/研究者——高频「截一块 → 识别/翻译/贴图/搜文件」
- **使用场景**：
  1. 主配置窗口是「功能枢纽」：改热键、看快捷功能、进模型/外观/历史
  2. 本地搜索是独立小窗：唤出即搜，键盘流
  3. 识别结果是结果窗：OCR 文本 / 表格 / 二维码，操作是复制
  4. 划词助手是轻量浮层：翻译/解释进行中
- **观众距离**：1m 笔记本桌面窗口；不是手机，不是投影
- **信息密度**：高密度工具型（AI/数据/上下文感知类例外，需 ≥3 处可见产品差异化信息），但**不堆装饰 icon**

## 情感基调与气质关键词

冷静、精准、轻快、可信、现代、工具感强  
**不要**：科技营销感、SaaS 落地页感、游戏感、儿童感  
**要**：像一件设计过的桌面精密工具，而不是又一个「管理系统」

## 现有 UI 问题（重设计要解决）

1. 主色 `#1677ff` + Segoe UI = 通用 Ant 感，识别度低
2. 品牌紫 `#8b5cf6` 只出现在 High*lighter* 一词，与主色打架
3. 侧边栏 13 项平铺，分组标题弱，「快捷功能」与「设置」边界糊
4. 历史页顶部彩色渐变条 + 圆角卡 = 2020 通用 dashboard slop
5. 模型页 accordion + 表单字段过多时缺层级
6. search / recognition / action 各自为政，无统一组件语言
7. 图标是 mask 单色，风格统一但与 UI 质感脱节

## 输出要求（三版统一，硬约束）

- **形态**：高保真可交互 HTML 原型，**单文件自包含**（inline CSS + 少量 JS）
- **画布**：桌面设计板，默认 **1600 × 1000** 视口可滚动；内部模拟窗口按真实比例
- **架构**：一个 HTML 里并排/错落展示 **4 个模拟窗口**（用 macOS/Windows 窗口 chrome 包起来，可用简化 titlebar）：
  1. **主配置窗口**（约 1180×740）——含侧边栏导航 + 「快捷功能」主内容，侧边栏可点切换到「热键设置」或「模型」之一
  2. **本地搜索窗口**（约 720×520）——搜索框 + 分类 + 结果列表 + 底栏
  3. **识别结果窗口**（约 560×480）——OCR 文本结果 + 底部操作
  4. **划词助手浮层**（约 360×280）——翻译进行中 + 置顶
- **交互最低要求**：
  - 主窗口侧边栏可切换 2–3 个路由（home / 热键 或 模型）
  - 快捷功能 Tab 可切换截图/AI 等分组
  - 搜索框有 focus 态；结果行有 hover/selected
  - 所有窗口 chrome 可关闭按钮 hover 态
- **真实文案**（必须用产品真实中文功能名，禁止 Lorem）：

### 侧边栏导航
快捷功能 · 工具箱（翻译 / AI 对话 / 截图历史 / 本地搜索）· 个性化（外观配色 / 插件）· 设置（界面设置 / 模型 / 功能设置 / 划词工具 / 热键设置 / 系统设置）· 关于

## 设计系统要求（每版必须自洽）

1. **自定义 CSS 变量**（不得沿用 `--primary:#1677ff` 默认感），在 `:root` 定义完整 tokens：
   - 颜色：bg / surface / surface-2 / line / text / text-muted / accent / accent-soft / danger / ok / warn
   - 半径、阴影、字号阶梯、字重、间距节奏
2. **字体**：必须有明确 display/UI 字体策略；开源可 Google Fonts 引用或系统栈，但 **禁止全场 Inter/Segoe/Arial 无个性**（除非风格 DNA 明确要求 system/Geist）
3. **组件语言**统一：导航项、按钮（primary/ghost/danger）、开关、芯片、列表行、卡片/分区、窗口 chrome、空状态
4. **反 AI slop**：
   - 禁紫渐变 hero、禁 emoji 当图标、禁圆角卡+左彩条 accent、禁 SVG 画人
   - 图标用 `assets/icons/*.svg`（相对路径 `./assets/icons/xxx.svg`）+ CSS mask 或 `<img>`；或 inline 简化 stroke SVG
   - 历史/截图缩略图用 CSS 几何「屏幕内容」占位，不画假照片
5. **一个细节做到 120%**：每版至少有一处「值得截图」的签名细节（排版 / 窗口层次 / 快捷键芯片 / 分割线 / 品牌字标）
6. **Light + Dark**：主窗口至少支持 light/dark 切换（角标或系统栏开关）；search 可暗可亮，与主语言一致
7. 中文排印：用「」不用 ""

## 文件与路径

- 输出到：`D:\workspace\Highlighter - 副本\design-demos\<你的文件名>.html`
- 图标目录：`./assets/icons/`（已就绪，45 个 SVG）
- 禁止 `_temp/`
- 禁止写生产代码（config.css 等）

## 自检清单

- [ ] 单文件可双击打开（无跨域 script）
- [ ] 4 个模拟窗口都可见且比例合理
- [ ] 主窗口导航可点，至少 2 个内容路由
- [ ] 无 Lorem，全是真实功能文案
- [ ] 无紫渐变/emoji图标/左彩条卡
- [ ] 有自己的 design tokens，不看起来像原版 Ant 蓝
- [ ] 1600×1000 下主内容完整可读

## 位置四问（每版自答后落实）

1. **叙事角色**：这是产品 UI 系统总览板（不是营销页）
2. **观众距离**：1m 桌面
3. **视觉温度**：冷静精准（可在框架内偏暖/偏冷/偏工业）
4. **容量**：4 窗口 + 侧栏 13 项 + 功能列表 11 行——必须留气口，禁止挤爆
