## 一、上一版为什么「不够美观」

上一版是按可测量的指标优化的（微软的 3:1 对比度标准），代价是把**所有让图标显得是被做出来的东西**都去掉了：平涂色块、普通圆角矩形、没有光、没有材质。它通过了一项测试，但看起来像一张工程图。

苹果的图标语言是**一套具体构造**，而「圆角方块上放个符号」只是它的表面印象。真正起作用的是四件事，平涂一个都不占：

### 1. 超椭圆（squircle），不是圆角矩形

上一版用的是 `rx=58` 的圆角矩形——直边和圆角在接缝处**曲率不连续**，眼睛读到的就是「一个盒子」。苹果用的是超椭圆 `|x|ⁿ + |y|ⁿ = 1`，曲率一路连续，所以它读起来像一个**物件**。

本版取 `n = 5`。这个数字不是猜的：45° 处曲线落在半宽的 `2^(-1/5) = 87.1%`，而苹果自家磁贴的同一位置大约在 87–89%。低于 n≈4 转角外鼓过头，高于 n≈7 又退回圆角矩形、失去效果。

曲线用 320 点采样生成，不是手调的贝塞尔。

### 2. 带**色相偏移**的本体渐变

从浅到深只改明度，会得到一个「被明暗过的平盘」。苹果的底板在变暗的同时**色相往橙红偏移**，这才是「被光照着的物体」的读法。

琥珀版：`#FFDDA8 → #F2AB48 → #C8731A`。渐变中点正好落在产品 `--primary` 的 `#E5A44C` 上——品牌色是这枚底板的**平均值**，不是近似值。

### 3. 方向光，不是径向光团

第一轮我用了径向高光（`radialGradient` 在顶部中心），结果是一团柔和的**光斑**——那是渐变模板的指纹。改成：

- 一条大面积**线性**衰减（顶亮底暗）
- 再加一条紧贴顶边的窄亮带（光掠过上表面的那一下）

用 `tools/lightmodel.mjs` 把四种光模型并排渲染在 256px 上比过，方向光 + 顶带这一组才读作「有光落在表面上」。

### 4. 底部接触阴影

底板下缘压暗一档，给它**厚度**。没有这一步，磁贴会像一张贴纸浮在那里。

### 5. 字形是自己的物体

上一版字形是平涂的白色，像剪出来贴在底板上。苹果图标里的字形有它自己的一套光：**自带竖向渐变**（纯白会显得像印上去的）、**柔和投影**（证明它落在底板上）、**上缘细高光**（接和底板同一束光）。

## 二、24px 及以下单独重画（这是苹果自己的做法）

iOS 图标在每个尺寸都是**单独调过的帧**，不是一个图缩下去。原因在评审板的 16px 那一栏里看得见：缩放版的 SWIPE 笔触和 LAYERS 叠层会糊成一片琥珀，因为 16px 下 40u 的元素只有 2.5px，字形自身的渐变和投影把它吃掉了。

所以 24px 及以下换一套画法：

| | 32px 以上 | 24px 及以下 |
|---|---|---|
| 字形占比 | ~55% | **~68%**（小尺寸需要更大的记号） |
| 字形渐变 | 有 | **去掉**（会糊） |
| 字形投影 | 有 | **去掉**（会糊） |
| 底板高光/顶带 | 有 | **去掉**（只剩本体渐变） |
| 上缘 1px 高光 | 有 | **去掉** |
| SWIPE 笔触 | 44u 带收锋 | **52u 无收锋**（22px 时收锋看不见） |
| CAPTURE 框线 | 24u | **32u**（否则只剩 1.5px） |
| LAYERS 层数 | 3 层半透明 | **2 层实色**（第三层是糊） |

`tools/smallframes.mjs` 里有缩放版与重画版的逐尺寸对照。代价是每个方向要维护两套 SVG——这是苹果自己承担的成本，我认为值得，因为 16px 是任务栏里唯一定会出现的尺寸。

## 二点五、独立评审发现的三个几何缺陷（已修）

交付前做了一次只读的独立评审，它在 256px 上指出了三处**具体**问题。我逐条复算确认后全部修掉，记录在这里因为它们比「看起来还行」有用得多：

| 缺陷 | 复算确认 | 修法 |
|---|---|---|
| SWIPE 的收锋**只在单边**：上缘从 x=150 开始下斜，下缘却平直到 x=186，读作被斜切过的楔形，不像笔锋离开纸面 | 属实 | 改为**两端都圆、半径不同**（落笔 22u → 收锋 15u），压力衰减由半径差承担，而不是一个平切面。中途试过「两端向中心线收拢」，但那会在末端留一个垂直切面，看起来像马克笔笔头——已否决 |
| CAPTURE 的**内孔是直角**：外框 r=22，内孔 r=2（84×84 的洞），圆角只占 2.4% | 属实 | 内孔改为 r=14（占洞宽 16.7%，与外框自身比例一致） |
| LAYERS 整组**偏右**：三块板在 70/86/102，跨度 70..206，中心 138 而画布中心 128 | 属实 | 整组左移 10u 到 60/76/92，跨度 60..196，中心归 128 |

评审还提出「三枚图标共用同一套底板光，橙色像素 66% 相同」。这一条**我没有改，因为它不是缺陷**：同一产品系列的图标本来就该共用同一材质与同一光源方向——苹果自家整套应用图标就是同一个光源。真正的错误是三枚各自打光，那才会读成「三个不同的 App」。

评审最后建议留 CAPTURE。我保留这个判断的记录，但推荐仍然是 SWIPE：理由见下节。

## 三、三个方向

| 方向 | 主角 | 概念 |
|---|---|---|
| **SWIPE 一笔** | 落下的那一笔 | 高亮笔只有一个动作：左端圆润落笔，向右逐渐收锋——笔压离开纸面时变细。产品名就是这一笔 |
| **CAPTURE 取景** | 被框住的那一块 | 截图与录屏是同一个手势：拉一个框。琥珀色记号落在框内——被选中的那块被标住了 |
| **LAYERS 浮层** | 叠起来的那一摞 | 截图浮层、贴图、剪贴板、用量面板，是同一个物件在四个深度上的出现；层叠本身就是「五功能合一」 |

**推荐 SWIPE。** 三个里最像苹果——苹果最强的工具类图标都是一个手势、一个形、没有配件（备忘录、提醒事项、语音备忘录都是这个结构）。而且 16px 重画后它是一条干净的白杠，是三个里最稳的。

**CAPTURE 语义最强**（截图/录屏/贴图都从「拉一个框」开始），深色版面在任务栏里最稳，代价是「框内再套记号」结构最复杂。

**LAYERS 融合叙事最强**，但 16px 下第三层必然消失，语义对单一功能最不具体。

| 角色 | 值 | 来源 |

| 琥珀 · 亮 | `#FFDDA8` | 本体渐变上端 |

**没有引入新颜色。** 琥珀就是产品的 `--primary`，深墨取自 `--ink`，米白取自 `--surface`。用户在设置里改主色时，把三个琥珀值换掉即可，其余不动。

## 五、已知不足

1. **两套帧的维护成本是真实的。** 每个方向有 large / small 两份 SVG，改设计要改两处。
2. **超椭圆的观感偏「苹果」而非「Windows」。** Windows 11 的图标多数是圆角矩形（PixPin、Snipping Tool、PowerToys 都是），超椭圆会让它在这类邻居中显得更「iOS」。这是风格选择，不是缺陷——但如果目标是「看起来像 Windows 原生应用」，应改回圆角矩形。
3. **`assets/icon.ico` 仍是旧的蓝色圆环。** 未替换。
4. **CAPTURE 的深色版在浅色任务栏上是一块深色磁贴。** 这与 Snipping Tool 等白色底板图标是同一类取舍（详见 `refs/SOURCES.md` §3b 的实测）。
