# 图标替换记录 · CAPTURE（取景）

> 用户选定方向：**CAPTURE 取景**（截图与录屏是同一个手势——拉一个框；琥珀色记号落在框内）。
> 本文记录**实际替换进产品**的改动、验证结果与后续维护方式。

## 一、改了什么

| 文件 | 变化 |
|---|---|
| `assets/icon.ico` | 旧图标（蓝色圆环）→ CAPTURE，**11 档尺寸** |
| `assets/icon.png` | 旧图标 → CAPTURE 浅色主题托盘源（256×256） |
| `assets/icon-dark.png` | 旧图标 → CAPTURE 深色主题托盘源（256×256，反转材质） |
| `generate-icon.js` | 逐像素绘制 → **SVG 光栅化 + ICO 打包**（详见下节） |

| `design-demos/app-icon/tools/rasterize-capture.mjs` | 新增：按尺寸光栅化（含小尺寸重画规则） |

## 二、`generate-icon.js` 为什么重写

旧版在 JS 里用双层循环逐像素画图（蓝色圆盘 + 三道白色轨道环）。新图标需要超椭圆、四层渐变、投影与 even-odd 圆环——这些不值得再用逐像素数学重写一遍，而且那会变成**两份平行的绘图代码**（设计稿一份、生成器一份），迟早不一致。

所以生成器现在只做三件事：读 SVG 母版 → 光栅化 → 打包。SVG 母版提交在 `design-demos/app-icon/assets/`，因此**不装设计工具链也能跑 `node generate-icon.js`**。

生成器自己实现了 PNG 读写（含 5 种扫描线滤波的解码）与 ICO 容器写入，**没有新增任何依赖**——旧版也是零依赖，保持这一点。

## 三、两套尺寸制度（关键）

图标在 **24px 及以下换一套画法**，不是缩放：

| | 32px 以上 | 16 / 20 / 24px |
|---|---|---|
| 取景框线宽 | 24u | **32u**（否则只剩 1.5px） |
| 内孔圆角 | r=14 | r=14 |
| 字形渐变 / 投影 | 有 | **去掉**（会糊） |
| 底板高光 / 顶带 / 1px 边缘 | 有 | **去掉** |
| 记号高度 | 34u | 28u（比例反而更大） |

这条规则一开始被我漏掉了：第一版所有 ICO 帧都从大尺寸母版渲染，交付验证时发现 **16/20/24 三帧明显发软**。修正后小尺寸帧改用重画版，锐利度立刻回来。`out/shipped/shipped.png` 里能看到修正后的结果。

## 四、托盘与应用图标必须一致（一次判断失误的修正）

### 最初的做法（错的）

我为深色任务栏做了一个**反转材质**的托盘变体：暖白底板 + 石墨框 + 琥珀记号。理由是石墨底板在 `#202020` 上自身边缘只有 1.07:1，会「化掉」。

这个版本交付后，用户在深色系统主题下看到：桌面快捷方式是**深色**图标，托盘是**浅色**图标——**看起来像两个不同的应用**。

### 为什么错了

把「底板边缘可见」当成了必须满足的约束，但实测表明它是图标里**最不重要的部分**：

| 元素 | 对深色任务栏 `#202020` |
|---|---|
| 米白取景框 `#F9F5EC` | **14.97 : 1** ← 眼睛真正读到的 |
| 琥珀记号 `#F0A944` | **8.12 : 1** |
| 石墨底板边缘 | 1.07 : 1 ← 唯一丢失的 |

取景框和记号才是图标本身，底板只是容器。**为了救一个 1.07:1 的容器边缘，牺牲了整个产品的品牌一致性**——这个交易是亏的。

### 现在的做法

三个资产**使用同一材质**：`capture-app.svg`、`capture-tray-light.svg`、`capture-tray-dark.svg` 全是石墨底板 + 米白框 + 琥珀记号。

深色任务栏变体**只差打光，不差色相/极性**：

| 参数 | 浅色任务栏 | 深色任务栏 |
|---|---|---|
| 顶部高光 `spec` | 0.18 | **0.30** |
| 顶边亮带 `edge` | 0.30 | **0.48** |
| 底部接触阴影 `shade` | 0.30 | **0.40** |
| 上缘 1px 高光 `rim` | 0.30 | **0.52** |

即在深色背景上让底板的**上缘多接一点光、下缘多压一档**，靠明暗把形状托出来，而不是换个颜色。

对照实测见 `out/tray-consistency/`（石墨款 vs 反转款并排），结论是石墨款在深色任务栏上依然清楚，且与桌面图标是同一个应用。

### 仍然保留两份资产的理由

`tray-icon.js` 的机制（浅/深两文件）本身是对的，也仍然有用：深色变体的打光更适合深色任务栏。只是**变化幅度必须是打光级别，不能是材质级别**。

## 六、后续怎么改这个图标

```bash
# 1. 改设计：编辑 design-demos/app-icon/tools/capture-source.mjs 里的几何/材质
# 2. 生成矢量母版
node design-demos/app-icon/tools/capture-source.mjs
# 3. 光栅化（大小两套尺寸制度）
node design-demos/app-icon/tools/rasterize-capture.mjs
# 4. 写入 assets/
node generate-icon.js
# 5. 确认交付资产在真实环境里没问题
node design-demos/app-icon/tools/verify-shipped.mjs
```

`.tmp/build/` 里的中间帧是可复现产物，已被仓库根 `.gitignore` 第 13 行的 `.tmp*/` 覆盖，不会进版本库。

## 七、需要人工确认的一件事

`assets/icon.ico` 已替换，但**安装包图标、开始菜单、文件关联图标需要重新打包才会更新**（`npm run build:win`）。另外 Windows 有图标缓存，替换后如果仍显示旧图标，执行：

```powershell
ie4uinit.exe -show
```

图标缓存不在本次自动化能覆盖的范围内，这一条必须肉眼确认一次。
