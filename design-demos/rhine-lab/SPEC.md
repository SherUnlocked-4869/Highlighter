# Highlighter · 莱茵生命风格 UI 重设计 — 设计 spec

> 这是三个方向的**共同输入**。只写「要说什么」，不写「长什么样」——长什么样是各方向卡的事。
> 项目目录：`design-demos/rhine-lab/`

## 1. 项目是什么

Highlighter 是一款 Windows 桌面效率工具（v4.1.2，Electron），核心能力是**观察并归档屏幕上的信息**：
框选截图 → 标注 → OCR/识别 → 翻译 → 贴图/历史归档；外加划词工具栏、长截图、录屏。

它每天被打开十几次、每次停留几十秒。它不是内容产品，是一件**经常被使用的工具**，而且是
「先看，再取，再存」这一条链路上的工具——放大、取样、读数、编号、归档。

## 2. 受众与场景

- 主：需要频繁截图、取文、翻资料的中文 Windows 用户（开发者、研究员、学生、运营）。屏幕通常是 1920×1080/2K，多个窗口并排。
- 次：重度用户（每天几十次截图，用快捷键，靠历史找回截图）。
- 场景：白天室内为主，夜间也常用（夜间在用「截图 + OCR」时屏幕内容亮、工具窗口要压得住）。
- 情感基调：**冷静、精密、可信、有机构感**。不是可爱、不是炫技、不是「AI 感未来主义」。

## 3. 核心信息（每屏要为它让路）

1. 我现在要怎么截 / 已经截了什么（选区与工具栏）
2. 这段字是什么（OCR 结果与翻译）
3. 我的东西存在哪（历史 / 贴图）
4. 这台工具现在是什么状态（识别在本地还是走 AI、热键是否冲突、版本）

## 4. 输出格式（三方向必须统一，否则没法横比）

- 单文件 HTML，`file://` 双击即开，零外部依赖（字体走系统栈，图标内联 SVG，图片 base64 或纯 CSS）。
- 画布：**1600×1000 展示板**（截图与验收统一这个视口；三版都在这个尺寸下完整可读）。
- 板面构成：**1 个主窗口（1120×760，可交互）＋ 3 个卫星窗口/局部**（截图选区浮层、OCR/翻译窗口、历史或贴图），
  外加一个「系统板」区（色值/字体/线宽/组件，证明这套能被工程落地）。
- 交互：主窗口内的导航、开关、页签、列表项、工具按钮**真的能点**，console 零报错。

## 5. 已知约束

- 中文文案为主，中西混排；正文中文 ≥14px，标签 ≥12px，正文对比度 ≥4.5:1。
- 不引用现有的 `#1677ff` Ant 蓝与 `#8b5cf6` 紫作为主色（那是旧设计的主要来源）。
- 不复制莱茵生命的官方 logo/图形资产做商用宣称；沿用的是**风格语法**（环、发丝线、编号、档案语法），不是复刻 logo。
- 三版共用同一份内容模型（真实文案，见 `src/content.js`），差异全部来自设计。
- 禁止：霓虹蓝紫 glow、绿字黑底终端、emoji 图标、圆角卡片 + 左彩条、渐变按钮、扫描线满屏。

## 6. 素材需求（三版共用）

- T0 档：无生图能力。主角素材 = **程序化材质与数据图像**（刻度环、档案盒、玻璃、线框、编号、真实产品截图）。
  真实产品截图：本项目自己就是产品，可用 CSS 构造的「被截取的屏幕内容」——但要诚实标注为示意。
- 图标：内联 SVG 线性图标，1.25–1.5px 描边，统一 16×16 / 20×20 网格（不用 emoji、不用 Bootstrap 原样）。

## 7. 验收

- `design_lint.py check` 无红灯；`compare` 三版不撞骨架；`ledger check` 与历史不撞。
- Playwright 截图看过、交互点过；1600×1000 下无溢出、无遮挡、无横向滚动。
