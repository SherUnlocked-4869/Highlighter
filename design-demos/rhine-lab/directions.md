## A1 · 白室导视 White Room Signage　【完整版 dir-1.html】

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | **最佳设计师 · Otl Aicher**（1922–1991，慕尼黑 1972 奥运会视觉系统、ERCO 企业系统、法兰克福机场导视）。他做的不是「图标」，而是**一套可扩展的导视语法**：网格、编号、无衬线、单一信号色。 |
| 借的是什么 | ① 水平/垂直两组对齐线构成的无框分区，分区之间只有 1px；② 每个功能区一个**几何原型图标**（方框=框选、横线组=文字行、圆+轴=固定）；③ 编号 01–04 压在角上；④ 信号绿/橙只出现在「当前所在」；⑤ 大标题走英文，中文只做并置小字。 |
| 主角素材 | **程序化制图**：四个几何原型图标全部用 CSS 方块/线条搭；被截取的屏幕内容用渐变+网格线诚实示意。 |
| 骨架 | 纸底 + 左上巨型英文标题 + 一条从右向左量出的 1px 线 + 四格等分功能区 + 页脚仪器状态行。 |
| 胆量花在哪 | 首屏**只有 4 个区、没有一个按钮**——功能区本身就是导航，靠图标与编号认路；其余全部让给留白与那一条线。 |
| form 来自内容的哪里 | Highlighter 的 28 项能力天然分成「截取 / 读取 / 固定 / 归档」四类，这四类就是导视牌上的四个目的地——**导视语法是这个产品真实的导航结构**，不是贴上去的比喻。 |
| 为什么它能当完整版 | 亮底纸感最接近官方 PV 的白室；分区制简洁、可工程化（1px 网格 + 4 色），且不会滑进「SaaS 落地页」。 |

## A2 · 测量台 Measurement Bench　【备选】

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | **最佳设计师 · 池田亮司（Ryoji Ikeda）**：datamatics 系列的纯黑背景、白线网格、巨号等宽数字、把「测量」本身当审美对象。 |
| 借的是什么 | ① 20px 网格底（4% 亮度）；② 十字准星贯穿全屏；③ 尺寸读数 46px 等宽数字 + px 单位降级；④ 底部刻度尺与键盘动词条；⑤ 右上双字段读数（MODE / CONF）。 |
| 主角素材 | 选区的真实尺寸与比例（1280×720 / 16:9）——**测量读数就是主角**。 |
| 骨架 | 全屏黑底 + 中心十字 + 巨号尺寸 + 底部刻度尺 + 顶部/底部 22px 状态条。 |
| 胆量花在哪 | 整屏没有一个可辨认的「按钮」，只有一个正在被量的矩形。 |
| form 来自内容的哪里 | 框选这件事的本质就是**量一个矩形**；把量出来的数字做成主角，是截图工具才有的版面。 |
| 未做完整版的原因 | 与 B2 同属暗底「仪器读数」气质，三版里会挤在一起；且「黑底巨号数字」离 B2 / C2 的区别不够结构性。 |

## B1 · 工作站 Workstation　【完整版 dir-2.html】

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | **现实参照 · Ableton Live 12**（Berlin，Ableton AG；同一媒介的桌面创作工具，界面以「左栏浏览器 + 双 lane 分栏 + 底部传输条」著称，灰色层级靠明度台阶而不是阴影）。 |
| 借的是什么 | ① 暖灰三阶（#D9D6CF / #CFCBC3 / #E6E3DB）做深度，零阴影零圆角；② 左栏分组浏览器 + 选中项左侧 2px 橙条；③ 内容区按功能分成并列 lane，每 lane 有角标计数；④ 底部「传输条」放状态与时间；⑤ 标题栏把窗口与产品名分开写。 |
| 主角素材 | **真实功能清单**（28 项，分 5 组）+ 真实默认快捷键（F1 / Alt+F / Ctrl+Alt+E）——工作站的「轨道」就是功能分组。 |
| 骨架 | 标题栏 + 左侧 224px 浏览器 + 右侧双 lane 功能板 + 字段行 + 底部传输条。 |
| 胆量花在哪 | 把「设置页」做成**一个可以一直开着的工作台**：不居中、不满宽、不留大标题，整屏都是可用信息。 |
| form 来自内容的哪里 | 这个产品 13 个路由里有 5 个是功能页（翻译 / AI / 历史 / 搜索 / 剪贴板），它本来就更像一个工作站而不是设置页——Ableton 的分栏密度正好装下这些并列的任务面。 |
| 为什么它能当完整版 | 与 A1 的「四个大区」骨架完全不同：这里是**高密度多栏工作台**；且它是唯一一个「不用力、纯工具」的方向，用户每天开合几十次最需要它。 |

## B2 · 取景器 Viewfinder　【备选】

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | **现实参照 · Halide Mark II**（Lux Optics，Apple Design Award；专业相机 App，界面为单手操作设计，深色 + 单一黄色焦点 + 横向刻度尺）。 |
| 借的是什么 | ① 近黑底 + 唯一信号橙只给当前参数；② 取景区四角实心方块；③ 底部横向刻度尺带指针；④ 工具列竖排在左；⑤ 顶部一行模式与工具计数。 |
| 主角素材 | 截图浮层本身（选区 + 四角手柄 + 尺寸徽标）。 |
| 骨架 | 全屏取景 + 底部 94px 仪器条（工具纵列 + 三条刻度）。 |
| 胆量花在哪 | 工具条全部改成**带指针的刻度尺**——线宽、缩放、置信度都用同一把尺子量。 |
| form 来自内容的哪里 | 截图浮层有 27 个按钮、两行都放不下；Halide 的「一行刻度 + 单一高亮」正是解决「按钮太多」的成熟答案。 |
| 未做完整版的原因 | 它本质上仍是 A2 的暗底仪器语言（同为暗底 + 读数 + 刻度），三版会撞气质；它的强项（浮层）会在三个完整版里作为**卫星窗口**出现，不浪费。 |

## C1 · 白盒 White Box　【备选】

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | **秒数轮盘 · 网页 20 号「日式留白白盒画廊 Kenya Hara White Gallery」**（原研哉『白』+ 瑞士网格；近全白、内容图提供全部色彩、UI 退到背景）。 |
| 借的是什么 | ① 近白底 + 唯一一件「物」居中；② 物件只靠 1px 边与 10% 投影浮起来；③ 图注在左下、编号在右下，两端对齐一条发丝线；④ 巨号计数 042 当版面重心。 |
| 主角素材 | 一张「被归档的截图」本身（示意为带网格的浅色矩形 + 编号标签）。 |
| 骨架 | 顶部两行元数据 + 居中物件 + 一条横线 + 左图注 / 右巨号编号。 |
| 胆量花在哪 | 一屏只有一件东西，且它只有 190×118。 |
| form 来自内容的哪里 | 截图历史本质是**作品集**；把每一张截图当展品陈列，是这个产品唯一「可以慢下来看」的角落。 |
| 未做完整版的原因 | 留给「安静」的预算太大：作为**整个产品**的界面，它会把高频功能（27 个工具栏按钮、13 个路由）逼进角落，实测会退化成 S3 那条教训「大片死白 + 微缩字号」。它更适合做「历史归档」单页，三个完整版里都会吸收它的陈列手法。 |

## C2 · 观测环盘 Observation Ring　【完整版 dir-3.html】

| 栏 | 内容 |
|---|---|
| 逻辑与来源 | **秒数轮盘 · 东亚 8 号「杉浦康平信息曼荼罗 Sugiura Information Mandala」**（同心环盘居中、外环刻度、中环扇区、内环小圆、竖排大标题、引线编号）。同时叠加 `brand-spec.md` 的暗底观测室 token 与「双环+正负号」的官方标志构成语法。 |
| 借的是什么 | ① 同心环盘当导航（四个能力各占一段弧）；② 极坐标刻度：一圈 60 格，当前扇区加粗；③ 竖排中文大标题 + 横排英文小标并置；④ 朱红扇区标记（对官方 PV 那一个橙色冒号的回应）；⑤ 环心是当前选中的能力，字号最大；⑥ HUD 读数贴在四角。 |
| 主角素材 | **程序化几何**：全部用 conic-gradient / 圆环 / 刻度线搭，零图片。 |
| 骨架 | 暗底满屏 + 居中直径 250px 环盘 + 右下竖排标题 + 左上 HUD + 底部仪器状态行。 |
| 胆量花在哪 | **导航是圆的**——四个能力沿圆周分布，方向键绕环走；这是三版里唯一一处「用力」的地方。 |
| form 来自内容的哪里 | Highlighter 的核心动作是「环状循环」：截图→识别→归档→再截图。环盘把这个循环画出来，而不是把二十几个功能排成一列。 |
| 为什么它能当完整版 | 它是三版里唯一的暗底与唯一的非矩形骨架；铜 + 朱红在近黑观测室里最像官方 PV 的那一点颜色。 |

## 选定的三张（完整版）

| 文件 | 方向 | 温度 | 骨架 |
|---|---|---|---|
| `dir-1.html` | A1 白室导视 | 亮 | 四格等分导视 + 巨标题 + 一条量出的线 |
| `dir-2.html` | B1 工作站 | 中性 | 左栏浏览器 + 双 lane 高密度工作台 + 传输条 |
| `dir-3.html` | C2 观测环盘 | 暗 | 居中环盘导航 + 竖排标题 + 四角 HUD |

三张彼此：亮 / 中性 / 暗；导视 / 工作台 / 环盘；一次性看懂 / 天天用 / 记得住。
