## 三个方向

### A1 · 哑光器物 MATTE（`dir-1.html`，亮色默认）
- **来源**：最佳设计师 · 深泽直人（without thought / 无意识设计；MUJI 壁挂 CD 播放器、±0 加湿器）
- **借的规则**：材质诚实（每种表面只说自己是什么）；**零装饰性发光**；选中＝被压进面板而不是变亮；颜色只有本体色 + 一个印刷色
- **主角素材**：程序化材质——SVG feTurbulence 细砂噪点 + 4 档表面明度台阶（L\*74.3 / 78.3 / 81.9 / 85.5）+ 1px 机加工接缝
- **骨架**：设备面板。左侧「机身侧边」比面板深一档（L\*57）+ 右侧面板 + 顶部铭牌行
- **胆量花在哪**：全界面没有一个渐变按钮、没有一处发光，层级只由「明度 + 接缝 + 砂面」表达
- **调色的一次转向**：初稿是暖中性灰，与 B1 的暖奶油产品界面距离只有 0.022（盲选会被读成「同一套换表面」）。最终改为**阳极氧化冷银**（#d3d6d9 / #bfc2c7 / #828a93 / 台面 #7e8388），暖只留在一个印刷色 #e5a44c 上——「冷金属上的一块丝印橙」。与 B1 的产品界面距离升到 **0.080**，整页 0.112。暗色是中性石墨（chroma 0.005–0.012，蓝通道仅高 6–10/255，不是蓝黑）
- **form 来自内容的哪里**：截图动作都是物理手势（拉框 / 落笔 / 钉纸），所以「当前工具」是**凹槽里被按下去的一枚键**，不是高亮的文字标签；侧栏与面板之间是垂直机加工接缝（分栏），内容分节是水平浅槽（分节）

### B1 · 浮层优先 FILM（`dir-2.html`，亮色默认）
- **来源**：现实参照 · CleanShot X（MTW，macOS 截图工具；2026-10-23 实拍官网 `refs/cleanshot-home.png`）
- **借的规则**：浮层是主角、主窗口只做设置面；圆角 14–20px；正文高对比 + 极少元素；暖中性玻璃（不是冷蓝玻璃）
- **主角素材**：一块 CSS 画出来的「假桌面」——玻璃必须有东西可透，否则就退化成一块灰（这一条是实测出来的：初版工具条背后是纯色区，blur 开/关的像素几乎无差，改法不是加 alpha 而是**改构图**）
- **骨架**：无边框圆角窗口浮在环境上；层级靠浮面高度 z0–z3（半透明度 + 模糊半径 + 双层阴影 + 1px 顶部内高光）分级，不用边框分级
- **胆量花在哪**：把浮层当成整套语言的语法——设置界面里的下拉、工具条、提示全部沿用同一套玻璃
- **一个需要你知道的取舍**：浮层玻璃的 alpha 从 0.62 提到 **0.78**，因为 0.62 压在白页上合成成中灰、正文实测只有 2.58:1（读不清的玻璃是雾）。现在浮层正文 5.67:1、主操作 7.62:1。**如果盲选时你觉得不够通透，这是唯一一个建议再试的参数**
- **form 来自内容的哪里**：这个工具 99% 的使用时间屏幕上只有一块浮层（框选 + 工具条），主窗口一年开不了几次；把浮层做成主角、主窗口降级成「浮层的设置面」，是这个产品独有的界面真相

### C2 · 珐琅铭牌 ENAMEL（`dir-3.html`，暗色默认）
- **来源**：秒数轮盘 · 东亚 6 号「香港街招与招牌」——**只取「刻字 + 牌面 + 单一光源」三件事，不做霓虹**
- **借的规则**：字是刻在材料上的，不是浮在背景上的；牌面 = 1px 奶白/黄铜描边 + 内阴影 + 4–8px 圆角；全页共享一个左上光源；朱红只给「当前」（全页 3 处），黄铜只做一次性引线
- **主角素材**：材料与光——暖棕珐琅面板 `#171310` + 奶白刻字 + **宋体正文**（Noto Serif SC）
- **骨架**：深色珐琅控制面板 + 大小不一的牌面拼贴；每块产品界面在评审板上套 **17px 黄铜装裱框**
- **胆量花在哪**：一个效率工具敢用宋体做正文，因为界面被当成一块刻着字的牌，而不是一块屏幕
- **一处诚实的布局说明**：功能列表 11 项 × 54px = 594px，而 760 高窗口的内容区只有 471px，单列物理上放不下。按真实产品行为处理——列表区可滚动，折叠处做牌面渐隐 +「↓ 还有 N 项」。1120×760 的窗口尺寸未改
- **form 来自内容的哪里**：截图工具输出的是被装裱起来的图；历史、贴图、识别结果最后都变成贴在桌面上的一块牌子——所以每块界面在板上都是一块被黄铜框装裱、字刻在牌面上的铭牌

## 最关键的一步：它们能落进真实产品窗口

原型只是我自己设计的 DOM。真正的问题是：**把方向的调色注入真实产品窗口，它还成立吗？**

`tools/landing-preview.js` 在**真实 Electron 渲染器**里跑这件事——真实窗口、真实安全配置
（`contextIsolation:true, sandbox:true`）、真实配置页路由、真实截图浮层/划词条/剪贴板面板，
把每个方向的调色映射到产品 token 名（`--bg/--surface/--line/--ink/--muted/--primary/--radius`）后注入，
截 30 张图并逐节点量对比度。

**结果：三个方向全部 30/30 表面通过，0 处新增低对比度文字，控制台零报错。**
主窗口、截图浮层（含选区 + 两行 27 控件工具条）、划词条、剪贴板面板都真实渲染出来了。

它同时挖出四个只有套进真实 DOM 才会暴露的问题，已写进 `TOKENS-PLAN.md`：

1. **产品缺一个「机身侧壁」token**——A1 的签名是「机身侧边比面板深一档」，但 `config.css` 里
   `.sidebar` 和 `.card` 同读 `--surface`，没有额外 token 就只能把深色放进内容区、侧栏反而更亮，
   签名被画反。**A1 需要新增一个 `--chrome`。**
2. **浮层必须固定暗色**——第一版让剪贴板跟随 app 主题，亮色档把它刷成浅底，4 个芯片掉到 3.3–3.8:1。
   浮层窗口要和 `settings.theme` 解耦。
3. **选区虚线是硬编码的旧主题蓝** `#36a3ff`（`capture/capture.js:737`），三个方向下都和新调色打架，
   而且它本来就是产品里第二个强调色。
4. **`--faint` 被用作 11px 分组标题**，三个方向初版都掉到 3.9–4.3:1；要么改用 `--muted`，要么给
   `--faint` 定一个最低亮度。

顺带确认了两个**不用改**：浮层暗底 + 白字在各方向都通过（说明「浮层永远暗色」是对的决策）；
13 个路由 × 双主题在三个方向下都无横向溢出。

判据是**相对当前 Nightshift 基线的回归**，不是绝对阈值——浮层里本来就有几处刻意低对比的文字
（8.5px 的「本地」徽标、截图提示条压在任意屏幕内容上），拿绝对 4.5:1 去判会把旧设计的账算到新主题头上。
这条判据本身也修正过一次：第一版用绝对阈值，报了 11 个「失败」，全都是既有设计。

## 每版都包含什么

1. **主窗口 1120 × 760（1:1 不缩放，实测 6/6 都是 1120×760）**：真实 13 个路由的分组侧栏（工具箱 / 工具设置 / 设置 + 关于）+ 标题栏 + 4 格状态轨 + 快捷功能（5 页签 + 11 项功能 + 快捷键键帽，含「未设置」虚线槽位与「冲突」警示态）+ 亮/暗切换
2. **截图浮层**：假桌面 + 选区（四角手柄 + 1280 × 720 · 16:9 徽标）+ 两行工具条（11 标注工具 / 颜色 / 线宽 / 12 动作 / 复制主操作 / 取消）
3. **剪贴板面板 480 × 640**：顶栏 + 状态轨 + 搜索 + 5 分类芯片 + 6 条记录（文本 / 链接 / 图片混合）
4. **划词工具条 620 × 56**：LED + 5 动作，复制为主操作
5. **动效演示台**：点一次播一次（≤1.2s），不循环；`prefers-reduced-motion` 全关

## 硬约束（三版共同遵守）

- **无网络字体**：每个窗口 CSP 都是 `font-src 'self' data:`。原型只用 Windows 已装字体（Segoe UI Variable / Microsoft YaHei UI / DengXian / Noto Serif SC / Cascadia Mono / Bahnschrift）——**你现在看到的字，就是用户装出来的字**。
- **强调色可配**（`settings.mainColor`，默认 `#e5a44c`）：实心强调色上的文字色用 oklch 亮度阈值算，强调色当文字用时只调亮度、保色相，用户换任何颜色都成立。
- 字号：正文 ≥14px、标签 ≥12px；正文对比度 ≥4.5:1。
- 动效只用 transform / opacity / filter，时长与曲线见 `SPEC.md` §4。

### 关于两条黄灯，如实说明

1. **`compare` 报「同一标题字体（Segoe UI Variable Display）」/「版式骨架相关 0.64」**：这是**系统字体约束下的必然结果**，不是设计雷同。桌面产品不能加载网络字体，Windows 上做 UI 标题只有 `Segoe UI Variable Display` 与 `Microsoft YaHei UI` 两个合理选择。骨架相关高，是因为**评审板规定五块演示按同一顺序排列**（主窗口 → 浮层 → 剪贴板 → 划词 → 动效），那是交付格式，不是设计。真正属于设计的是产品窗口内部：A1 冷银机加工面板 / B1 暖玻璃浮面 / C2 暖棕珐琅铭牌，产品窗口色板距离 0.080 / — / 0.205 起，是三种材料语言。
2. **`ledger check` 报 dir-1、dir-3 与上一轮 `highlighter-rhine` 撞色（0.051）**：撞的是**整页平均色**这个统计特征。上一轮被否的三版是暖纸底 / 中明度灰底 / 近黑底各一版，本轮同样是「一暗两亮」，整页均值必然落在相近区间。但**产品界面不撞**：上一轮是零圆角 + 1px 发丝线 + 9–11px 微标签 + 低对比暖灰；本轮分别是细砂冷银机加工、暖玻璃浮面、暖棕珐琅 + 宋体刻字 + 黄铜装裱。本轮已按账本要求让至少一个方向彻底离开最近反复出现的样子——dir-2 无命中，dir-1 从 0.037 拉到 0.112（整页口径）。
