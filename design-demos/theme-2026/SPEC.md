# Highlighter · 2026 主题重设计 · 三方向共同输入

> 这份 spec 只写「要说什么」，不写「长什么样」。长什么样是 `directions.md` 里每张方向卡的事。
> 三个方向必须共用本文件、共用 `content.js`，这样横向对比时差异全部来自设计。

## 1. 产品是什么（事实，来自 4.1.2 源码）

Windows 桌面效率工具 Highlighter：截图 → 标注 → OCR / 表格 / 二维码识别 → 翻译 / AI 对话 → 贴图 / 录屏 / 剪贴板历史。
Electron 43 + 原生 sidecar，**全部界面都是自绘 HTML**，共 11 个渲染窗口。

本次重设计只做**高频三窗**（用户已确认）：

| 窗口 | 尺寸 | 形态 | 用户接触频率 |
|---|---|---|---|
| 主设置窗口 | 1120 × 760（min 880 × 620） | 无边框 `frame:false`，自绘标题栏 + 224px 侧栏 + 状态轨 | 每天打开数次 |
| 截图浮层 + 工具条 | 全屏遮罩；工具条两行 27 个控件 | 浮在任意屏幕内容之上 | 每天几十次 |
| 剪贴板面板 | 480 × 640 | 无边框浮层，固定在暗色 | 每天十几次 |
| 划词工具条 | 620 × 56 | 跟随选区出现的小条 | 每天数次 |

## 2. 硬约束（不是审美偏好，是工程现实）

1. **没有网络字体**。每个窗口的 CSP 都是 `font-src 'self' data:`，`connect-src 'none'`。原型必须只用 Windows 已装字体——**你现在看到的字，就是用户装出来的字**。
   - 可用：`Segoe UI Variable Display/Text`、`Segoe UI`、`Microsoft YaHei UI`、`DengXian`、`Bahnschrift`、`Noto Serif SC`、`Noto Sans SC`、`Yu Gothic UI`、`Cascadia Mono`、`Consolas`。
2. **强调色是用户可配置的**（`settings.mainColor`，运行时以 inline style 覆写到 `<html>`），默认 `#e5a44c`。所以方向必须定义「任意用户色都成立」的规则：实心强调色上的文字色、强调色当文字用时的亮度修正。
3. **浮层永远暗色**（截图工具条、录制 HUD、长截图面板、剪贴板），因为浅色面板压在浅色文档上不可读。它们可以消费强调色与圆角，但底色不跟随主题。
4. **主窗口同时需要亮/暗两套**。方向必须两套都给，且不是简单反色。
5. **可读性底线（任一方向不豁免）**：正文 ≥14px、标签 ≥12px、正文对比度 ≥4.5:1、可点元素 ≥32px（桌面）/ ≥28px（浮层紧凑态）。
6. **动画只用 transform / opacity**（或 `filter`/`backdrop-filter` 这类不触发 layout 的属性），尊重 `prefers-reduced-motion`。
7. **无 emoji**、无 SVG 手绘插画、无编造数据。图标全部来自 `assets/icons/`（真实产品在用的 45 个 Bootstrap Icons），通过 CSS mask 继承 currentColor。

## 3. 用户要的「高级感」是什么（用户原话）

> 「有材质有温度：像一件真实的器物」

翻译成可验收的标准：

- 界面要像**一件被做出来的物件**：有表面处理（哑光 / 拉丝 / 玻璃 / 漆面）、有厚度、有接缝、有光；
- **不要**扁平 SVG 图标风 + 均匀圆角卡 + 灰阴影的「网页 dashboard」；
- **不要**把风格复刻当成目的：上一轮莱茵生命三版被否的原因是「零圆角 + 1px 发丝线 + 9–11px 微标签 + 低对比暖灰」牺牲了高频工具的扫描速度与亲和度。**这次细节要经得起看，但可读性和手感优先。**

「交互自然丝滑」是可验收的，见下。

## 4. 动效规格（三方向共用同一套物理感，避免一个比一个滑）

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 按压反馈 | 90–120ms | `cubic-bezier(.2,.7,.3,1)` | 下沉 1px + 阴影收紧，不等回弹 |
| 悬停/切换色 | 120–160ms | `ease-out` | 进快出慢 |
| 浮层出现/消失 | 180–220ms | `cubic-bezier(.16,1,.3,1)` | 位移 ≤8px + 淡入，不做缩放弹跳 |
| 面板/页面切换 | 220–280ms | `cubic-bezier(.22,.61,.36,1)` | 内容整体切换，逐项 stagger ≤24ms |
| 大表面（抽屉、浮层高度） | 260–320ms | `cubic-bezier(.22,.61,.36,1)` | 临界阻尼，无 overshoot |
| 指示器移动 | 180–240ms | `cubic-bezier(.3,.8,.2,1)` | 用 transform 平移，不用 left/top |

禁止：`ease-in` 出现在交互反馈里（会显得迟钝）、所有东西都 fade-up、无限循环装饰动画、bounce > 5%。

## 5. 三个方向必须回答的 form 五问

每个方向开工前在卡片里写清楚：

1. **叙事角色**：这一屏是每天都用的工作台，不是落地页。
2. **观众距离**：40–70cm 笔电/显示器，1120px 宽窗口；浮层更近、更快。
3. **视觉温度**：用户要「有温度」——温暖不等于暖色，也可以用材质与光。
4. **容量估算**：主窗口 13 个路由（12 在侧栏 + 关于）、首页 11 项功能 + 5 页签；截图条 27 个控件；剪贴板 42 条记录。密度是硬需求。
5. **视觉母题**：这个产品独有、别的题材不会有的东西是什么？（答不出＝还在靠风格标签抽签）

## 6. 交付形态

- 每个方向 **1 个自包含 HTML**：`dir-1.html` / `dir-2.html` / `dir-3.html`（源码在 `src/`，由 `tools/build.mjs` 注入图标与内容）。
- 每版必须同时展示：主窗口（亮/暗可切）+ 截图浮层工具条 + 剪贴板面板 + 划词工具条。
- 交互必须真的能点：路由切换、页签切换、明暗切换、工具选择、列表选择、开关、抽屉/浮层出现。
- 页面里放一个「交互演示」区，能一键播放关键动效（不是自动循环）。
- 1600×1000 截图 + 控制台零报错 + 无横向滚动。
