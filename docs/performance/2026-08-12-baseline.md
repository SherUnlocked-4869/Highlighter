- 版本：`2.1.0-beta.0`
- 系统：Windows 11 build 26200 x64

- 内存：48,282 MiB

## 1. 采集边界

本报告建立性能优化前的首份可重复基线。算法、历史扫描和模块加载由
`npm run bench:performance` 自动采集；运行中应用的进程快照通过
`npm run bench:performance -- --include-running-app` 附加。

运行中应用快照受当前已打开/隐藏窗口影响，只用于发现资源生命周期问题，不能直接作为优化后的验收值。
正式比较必须固定操作序列，执行至少 5 次，并使用中位数与 P95。

本次提交同时在本地结构化日志中加入以下 `performance` 事件：

- `startup.services-ready`
- `main-window.ready`
- `main-window.reopen`
- `capture.interactive`
- `ocr.recognize`
- `history.list`
- `history.sources`
- `history.stats`

`main-window.ready` 与 `capture.interactive` 后还会写入 `performance-snapshot`，通过
Electron `app.getAppMetrics()` 记录各进程类型的 Working Set、Private Memory 与 CPU。
事件只包含时长、尺寸、模式、缓存命中和资源汇总，不记录截图、OCR 或划词内容。

## 2. 自动基准结果

### 2.1 长截图匹配

| 场景 | 检测结果 | Median | P95 |
|---|---:|---:|---:|
| 4K 垂直分析帧，96×2160，位移 360 | 360，matched | 161.04 ms | 163.07 ms |
| 4K 水平分析帧，3840×96，位移 640 | 640，matched | 127.78 ms | 129.78 ms |

当前长截图采样间隔为 180 ms。垂直匹配的 P95 已占采样周期约 91%，是首批持续 CPU 优化目标。
优化门槛为 4K P95 小于 50 ms，并保持语料集的位移与状态完全一致。

### 2.2 历史扫描

临时目录创建 200 条、每条 1 KiB 的有效历史文件；每项运行 10 次。

| 场景 | Median | P95 |
|---|---:|---:|
| 首 40 条分页 + 来源列表 | 10.41 ms | 16.65 ms |
| 统计 + orphan 目录扫描 | 12.39 ms | 15.17 ms |

该结果来自本机 SSD 和小文件，只证明当前上限为 200 条时本地路径尚未超过 50 ms。
后续需要补慢盘/失效路径场景；主进程中的同步 I/O 仍应移除，避免阻塞截图与划词。

### 2.3 冷加载模块

每个模块在独立 Node 进程中加载 5 次，不包含进程启动时间。

| 模块 | Median | P95 |
|---|---:|---:|
| `sharp` | 31.18 ms | 33.19 ms |
| `electron-updater` | 55.65 ms | 57.88 ms |
| `screenshot-desktop` | 12.93 ms | 13.57 ms |

这不是 Electron 主进程的完整冷启动时间，但说明 `sharp` 与 `electron-updater` 值得在真实
`main-window.ready` 数据稳定后评估延迟加载，预计上限约为几十毫秒而非主要性能收益。

## 3. 当前运行资源快照

采集时应用处于运行状态，窗口历史不受控：

| 指标 | 数值 |
|---|---:|
| Highlighter/Electron 进程 | 6 |
| OCR sidecar | 1 |
| 合计 Working Set | 581.4 MiB |
| 合计 Private Memory | 387.1 MiB |
| OCR sidecar Working Set | 54.9 MiB |

这份快照确认应建立“主窗口隐藏、无 action/capture/pin、OCR 已超过空闲期”的标准托盘场景。
后续目标是在该受控场景下降低 20%–30% Working Set，同时保持主界面重开与划词响应 P95。

## 4. 包体积快照

| 指标 | 数值 |
|---|---:|
| `win-unpacked` | 502.77 MiB |
| Electron locale | 55 个 / 46.65 MiB |

locale 精简属于低风险包体积目标。FFmpeg、OCR runtime/model 的可选下载会改变离线能力，
不与本轮运行时优化混在同一提交。

## 5. 下一步测量顺序

1. 用新日志对冷/热启动、首次/再次截图和冷/热 OCR 各执行 5 次，记录 Median/P95。
2. 对 24 FPS、1080p 与 4K 录屏记录 5 分钟 CPU、GPU、Working Set、掉帧和转码时间。
3. 建立长截图真实语料，覆盖文本、列表、图片、双向滚动和静止帧。
4. 固定主窗口关闭后的托盘空闲场景，区分 Browser、Tab、GPU、Utility 和 OCR sidecar。
5. 所有优化提交附带 before/after；收益不足 10% 且增加复杂度的实现不保留。
