# 长截图匹配性能优化

- 日期：2026-08-12
- 优化前提交：`a094197`
- 基准命令：`npm run bench:performance`
- 机器：AMD Ryzen 7 9850X3D，Windows 10.0.26200，Node.js 24.16.0

## 热点

`findBestShift()` 会穷举正反方向的所有候选位移。旧版 `scoreShift()` 在最内层循环中重复判断
横纵方向并计算二维数组索引，之后为数千个候选对象排序，还会再次计算最优位移附近的分数。

## 等价优化

- 横向评分改为逐行连续读取，纵向评分复用递增行索引，移除采样内层的方向分支和乘法。
- 使用固定大小的 `Float64Array` 保存候选分数，并在线跟踪最优分数，避免对象分配和全量排序。
- 细化阶段直接复用已计算的相邻分数，不再重复扫描像素。
- 仍逐一评估原有全部候选位移；采样点、分数、阈值、置信度和歧义判定公式均不变。

## 基准结果

每项对同一确定性 4K 分析帧运行 5 次：

| 场景 | 优化前中位数 | 优化后中位数 | 降低 |
|---|---:|---:|---:|
| 垂直，96 × 2160，位移 360 | 164.75 ms | 56.28 ms | 65.84% |
| 水平，3840 × 96，位移 640 | 126.35 ms | 86.23 ms | 31.75% |

该结果是匹配器 CPU 墙钟时间，不包含桌面取帧、Canvas 缩放、PNG 编码或磁盘拼接。

## 正确性验证

- 长截图功能测试覆盖正向、反向、横向、纵向、静止画面、重复纹理拒绝和最终图片拼接。
- 新增参考评分器，对横纵方向和正反位移逐值校验评分结果。
- 额外将优化前后算法在 120 组确定性随机位移帧上逐字段对比，`status`、`shift`、`score`、
  `stillScore`、`margin` 和 `confidence` 完全一致。
