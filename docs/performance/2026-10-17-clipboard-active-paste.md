# 剪贴板历史主动粘贴（T17）开发记录

后续实机发现：文本主动粘贴在发送前被 `CLIPBOARD_CHANGED` 取消，手动粘贴可用。修复设计、证据边界及验收计划见 [主动粘贴失败修复方案](../plans/2026-10-17-clipboard-active-paste-fix-plan.md)；此链接不代表修复已实施。

依据本次明确要求，在记录详情的复制、置顶、删除操作区增加“粘贴”。点击记录仍只选择；双击记录和列表 Enter 仍执行复制。粘贴是单独的显式操作。历史默认关闭保持不变。

## 使用方式与结果

1. 在目标应用的输入框放好光标，通过历史快捷键呼出面板。
2. 选择文字、链接或图片记录，点击“粘贴”。
3. 后台读取完整原件并写入剪贴板，收起历史面板，恢复原窗口，核对原焦点，再发送一次 Ctrl+V。详情的 64 KiB 显示截断不影响实际写回。

从 Highlighter 自身设置页打开面板时，无法认定之前的外部输入框，只复制并提示手动粘贴。目标应用须支持 Ctrl+V 和对应的数据格式；文本输入框不能接收图片时，不转换成路径或替代文本。终端专用 Ctrl+Shift+V / Shift+Insert 策略未引入。

结果分三类：

| 结果 | 行为 |
| --- | --- |
| `injected` | 完整四个键盘事件已经进入 Windows 输入流，面板保持隐藏；不声称目标已消费内容 |
| `copiedOnly` | 已执行记录复制，但没有发送粘贴；目标失效、窗口切换、按键占用、系统拒绝输入等情况保留手动路径 |
| `PASTE_OUTCOME_UNKNOWN` | 写入/注入阶段发生超时、进程中断、部分事件插入或回执提交失败；提示先检查输入框，不自动重放 |

若复制之后剪贴板被其他操作改动，则取消发送，不能把新内容误粘贴。焦点切换或剪贴板改动导致的取消不重新弹出面板；其他失败可用 `showInactive` 展示提示，不抢输入焦点。隐藏期间发生的失败不会变成自动重试。

## 实现与边界

- `main/domains/clipboard/index.js`：在隐藏窗口显示前捕获前台目标；只在当前历史窗口可见且持有焦点时接受粘贴。准备完成后再次验证窗口、显示世代和系统状态。用户失焦/关闭/进入游戏模式/迁移期间取消提交。立即释放设置会延迟实际销毁到在途请求完成；停用和退出仍立即隐藏界面并阻止后续提交。
- `clipboard:paste`：专用 clipboard 角色，仅接受记录 UUID 与 operation UUID。页面不能提供窗口句柄、进程 PID、快捷键、目标或提交票据。主界面及其他角色没有这个通道。目标 ID、HWND 和一次性提交票据只走父子进程私有 stdio。
- `native/clipboard/src/paste.rs`：保存前台 HWND、输入焦点 HWND、线程/PID 和原进程 HANDLE；保留 HANDLE 并检查进程存活，防止 PID 复用。检查窗口仍存在、仍属原进程/线程、焦点仍位于同一顶层窗口、目标不是本应用进程、输入桌面与当前桌面一致。目标有效期五分钟，下一次呼出重新捕获；隐藏撤销。
- `paste.prepare` 先记录 pending receipt，再复用 Unicode / PNG + DIBV5 写回及图像内存限额。原件读取/解码之前获取现有协调屏障。写入成功后只保留序列号、目标与票据，不保留第二份图片缓存。
- `paste.commit` 消费一次性票据，限三秒内提交，再获取协调屏障。短暂无前台状态最多等待 100ms；恢复焦点及等待 Ctrl/Alt/Shift/Win、V、鼠标按钮释放合计最多 300ms。只允许原目标或历史面板作为前台，遇到第三方窗口立即取消。按键发送前再次验证桌面、实际前台、原焦点及剪贴板序列。
- 标准 Ctrl+V 四事件单批发送一次。不会先强制释放用户按住的修饰键，不使用跨线程 AttachThreadInput、模拟 Alt、提权或旧剪贴板恢复。部分插入只清理本批已插入的按下事件，并按未知结果处理，不补发粘贴。
- 使用已有有界 `operation_receipts`（保留最近 256 个完成/在途操作的现行机制）：复制与粘贴指纹隔离；重复 UUID 返回已完成结果或未知错误，不重新执行副作用。票据同时只能存在一个；重启丢失在途票据不会恢复发送。该去重保证受现有回执保留窗口约束，不是无限期的历史 UUID 注册表。
- `ClipboardService` 的超时、退出和主动终止都把在途 `paste.prepare` / `paste.commit` 映射为未知结果；恢复后台只恢复服务，不重放操作。
- 增加简中、英文和繁中按钮、提示和错误文案；粘贴反馈单独显示，不被两秒健康状态更新覆盖。

Windows 前台切换和 SendInput 之间没有原子“只投递到这个窗口”的 API。最后一次核对尽量贴近发送，仍存在操作系统调度期间焦点/剪贴板变化的极短竞态；不能声称彻底消除。基于 HWND 的焦点校验也不能识别浏览器同一原生容器内 DOM 光标的所有变化。系统输入流插入成功不能证明目标实际粘贴成功；这是实机验收必须覆盖的边界。[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)、[GetGUIThreadInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo)。

## 资源占用

新增功能不创建常驻线程、全局键盘/前台监听器或周期轮询；沿用已有后台和健康检查。目标/票据各一个，保存少量元数据和一个进程 HANDLE；仅显式点击时执行有期限的等待。图片仍走现有串行重任务屏障，提交阶段不再读取/解码图片。隐藏后沿用已有面板释放策略，操作在途时只延后窗口销毁，不长期维持图片缓存。

这些是实现约束，不是实测资源结论。新增原生文件对 exe 体积、真实工作集、事件发送可靠性及整进程树内存变化仍需验收。
