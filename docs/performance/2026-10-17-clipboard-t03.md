## 已实现的行为

### 采集屏障

`native/clipboard/src/barrier.rs` 维护 Idle、Pending、Active、Orphaned、Closed，以及独立的通知世代。消息窗口只读取发布的原子世代；它不等租约、不读正文。

采集线程必须在读取系统剪贴板之前持有 read permit。begin 先进入 Pending 并改变世代，再等待已有 permit 释放；最多等待 60 ms。旧快照即使稍后返回，也不能在世代失效后被当成当前候选。只有活跃读取全部退出，才能发送 grant。没有 grant，native worker 不允许清空、复制或恢复。

end 更新当前序列基线并改变世代：租约内排队的通知失效，延迟到达且仍指向结束基线的通知不会重读。只比较序列是否相等，不把起止序列之间的区间认作“自己写的”，因此不受普通跳号、回绕影响。

### 专用命名管道

`native/clipboard/src/coordinator.rs` 提供原生通道；原有 stdio 继续承担父进程控制。

- 管道名称、nonce、hostEpoch 分别使用 BCrypt 系统 RNG 的 32 字节随机数。
- DACL 只授权当前 logon SID；注册时比较宿主和后台的 logon SID、Windows session。明确拒绝远程客户端。
- 后台持有已注册宿主的进程 HANDLE；每次连接核对系统报告的客户端 PID，并检查该 HANDLE 尚未结束。PID 重用不能替代这个存活检查。
- addon 核对系统报告的服务端 PID；配置只接受指定前缀与长度的管道名、64 字符十六进制凭据（256 bit）和本进程的 hostPid。
- 随机凭据只经父子私有通信和宿主私有消息传递，不放到命令行、持久设置、普通诊断或 renderer。
- 使用 overlapped I/O 和事件等待。正常空闲不轮询；读取有期限，失败后有可取消的 25 ms 退避，避免异常重连忙循环。

这些权限选择依据 [Microsoft 命名管道权限说明](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)。

### 固定包协议 v1

这是独立的 native worker 通道，不替代 stdio 的受限帧格式。请求固定 128 字节、回复固定 32 字节，无正文、无动态长度分配；整数均为 little-endian。

| 请求偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 4 | `HLC1` |
| 4 | 4 | 操作：1 begin，2 end |
| 8 | 8 | 非零、在当前宿主注册期内递增的 transaction ID |
| 16 | 32 | nonce |
| 48 | 32 | hostEpoch |
| 80 | 8 | begin 为零；end 为授予的 lease generation |
| 88 | 20 | beforeClear / afterClear / afterRead / beforeRestore / afterRestore，五个 u32 观测点 |
| 108 | 4 | end outcome：1 restored、2 interrupted、3 ambiguous |
| 112 | 16 | 保留，必须为零 |

begin 的 80–111 字节必须全零。end 的 interrupted 同时表示未改写即取消，因此无需另一种 abort 包；已经 grant 而未完成 end 的断连一律进入 orphaned。

| 回复偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 4 | `HLC1` |
| 4 | 4 | 0 成功，1 拒绝 |
| 8 | 8 | transaction ID |
| 16 | 8 | lease generation |
| 24 | 4 | 服务端租约期：2000 ms |
| 28 | 4 | 保留，必须为零 |

客户端从开始连接起给 grant 整个过程最多 100 ms，只在 native worker 等待。客户端写入有效期更短，为开始连接后 1500 ms，并在实际改写前重新检查连接、配置修订及有效期。公共同步取词 API 在配置了协调器时不会等管道，其 UIA/MSAA 路径仍可使用。

### 恢复与备份保护

`vendor/selection-hook/src/windows/lib/clipboard_transaction.*` 将备份、清空、读取和恢复纳入 RAII 生命周期，保持 UIA → MSAA → clipboard 的顺序及已有 Ctrl+Insert/Ctrl+C 重试时序。

键盘钩子先记录输入 serial，再应用原有“检索中不发事件”的过滤。快速按下/释放仍会增加 serial；只忽略本 addon 带私有 tag 的注入，其他工具的注入也视作中断。没有新增按键注入种类。

读取后记录精确序列、owner PID 和输入 serial。恢复先取得 `OpenClipboard`，然后在**同一个持锁区间**重新比较，才允许清空和写回；不能检查完再打开。目标应用的更新若在读取后改变序列，或实际复制/其他 owner 介入，就保留当前数据。若系统仍只有本事务的空值，可以恢复原备份；原本为空的剪贴板也可安全恢复为空。

创建 message-only owner HWND，避免 `OpenClipboard(NULL)` 后清空导致 `SetClipboardData` 失败的旧约束；依据见 [Microsoft EmptyClipboard 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-emptyclipboard)。

备份最多 64 个格式、累计 64 MiB；发现无法完整备份、超限或不支持的私有/GDI 格式即在清空前取消。读取选区文本时限制源分配为 2 MiB，并在分配边界内查找终止符；这是 selection-hook 的源读取保护，区别于历史采集线程的 1 MiB UTF-8 正文上限。所有借用的全局句柄均在错误/异常返回时解锁。

诊断仅含 leaseDenied、backupRejected、inputInterrupted、ambiguousInterleaving、restored、restoreFailed 等计数。协调器的最后完成记录只保留五个序列锚点、outcome 和基线；不包括凭据或剪贴板内容。

### 宿主私有消息

`SelectionHookService.configureClipboardCoordinator(endpoint)` 通过既有 utility/child 私有通道发送配置，等待当前宿主的确认；超时 500 ms。native 配置只在检索空闲时应用，然后异步做一次原生健康握手，不阻塞 JavaScript。

凭据不加入 startOptions，不在重启时复用。宿主替换时，未完成的配置立即失败；旧宿主的回调、旧 requestId 及迟到健康结果不能确认新宿主。错误映射为固定 code，不能转发含凭据的异常消息。

现有 heartbeat 只带回白名单中的 native 计数，主进程重新验证为非负安全整数，忽略额外字段并在宿主切换时清除，便于定位租约失败或备份超限；不回传连接凭据。

这只是供后续 T08 使用的私有接口，**尚无产品控制器自动调用它**。T08 必须保持记录暂停，确认旧宿主退出，注册实际新宿主 PID，等待配置确认与健康握手，再建立基线；不能把一次 postMessage 当作完成配置。

### 崩溃、租约到期与停写

grant 后断连、包不合法或服务端 2 秒期限到达，屏障进入 Orphaned。它不会按时间自动清除，也不会由后台替宿主恢复旧备份。recover 要求原注册进程 HANDLE 已 signal；宿主仍在运行时返回 `HOST_STILL_RUNNING`。

注册、移除和恢复协调器要求采集暂停。quiesce 会先停新采集，即使还有事务也不自动继续记录；事务未收口则返回 `COORDINATION_BUSY`，不谎报已经停止。成功关闭后才可移走数据文件。
