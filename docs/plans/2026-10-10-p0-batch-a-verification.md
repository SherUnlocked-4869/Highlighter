### 3.4 真机验收中发现并已修复的缺陷（高 DPI 下 PDF 分页）

**现象**：副屏（`DISPLAY2`，125% 缩放）上截取整屏高度的高选区（PNG **1440×2520** 物理像素）导出 PDF → **2 页**（两页 MediaBox 均 595.92×842.88 pt，A4 纵向）。

**根因**（受控探针 + PDF 内容流定位）：`pdf-export.js` 的 `scale` 是按 **DPI 换算后的 CSS 尺寸**（`pxW / dpi × 96` = 1152×2016）计算的，但 `capture/print.html` 的 `<img>` 实际按 **PNG 自然像素**（1440×2520）排版 —— 缩放因子因此差了 `scaleFactor` 倍（125% → 内容比页面高 25%），Chromium 于是分页。

**证据**（`.tmp/tall-probe.js`，真实 Electron 隐藏窗口，6 个用例）：

| 用例 | 图片排版尺寸 | scale | 页数 |
| --- | --- | --- | --- |
| 1440×2520 @dpi120（**修复前**） | 1440×2520（自然像素） | 0.5568 | **2** |
| 1440×2520 @dpi120 + CSS 尺寸钉到 1152×2016 | 1152×2016 | 0.5568 | **1** |
| 1152×2016 @dpi96（自然 = 换算值） | 1152×2016 | 0.5568 | 1 |
| 宽图 1000×400 @dpi120 | — | 1 | 1 |

**为何单测没抓到**：Wave 1 的探针用例都用默认 `dpi=96`（此时自然像素恰好等于换算后的 CSS 尺寸），差异被抵消。

**修复**（提交 `7727f0b`）：`computePaperOptions` 两个分支都返回 `intrinsicCssPx`，`exportPdfBuffer` 用它（而非 PNG 像素）作为注入页面的 CSS 尺寸 —— 排版与 scale 自此同源。

**回归覆盖**：两个模式的 `intrinsicCssPx` 单测断言 + 真实 Electron 探针新增 `1440×2520 @dpi120` 用例（该用例对全部用例断言"单页"）。

**连带修正**：高 DPI 屏上**宽图**此前也被多印了 25%（只是恰好没溢出），修复后恢复为图纸预期尺寸 —— 因此 `test-wide.pdf` 之类的产物在 125% 屏上会比修复前略小，属修正而非回归。

### 3.5 评审发现的第二项：留白贴左 → 已改居中

**现象**：修复分页后，高图 PDF 的右侧出现约 19% 纯白。核实结论：**留白本身是正确的等比适配结果**，但图被**贴左（上）**摆放，导致留白全堆在一侧，观感像缺陷。

**测量**（`.tmp/pdf-ctm.js`，逐 token 解释内容流的 q/Q/cm 变换栈 —— 之前用正则解析重复计了一次矩阵，得出过"被裁切"的错误结论）：

| 项 | 修复分页后 | 居中后（`a46bbc0`） |
| --- | --- | --- |
| 高图 1440×2520 @dpi120 的图片 bbox | x 0 → 481.08（页宽 595.92） | **x 57.63 → 538.70**（左 57.6 / 右 57.2） |
| 宽图 1920×1080 的图片 bbox | （原为顶部对齐） | x 0.88 → 842.70，**y 61.01 → 534.54**（上下各约 61，垂直居中） |
| 页数 | 1 | 1（全部 4 个探针用例） |

**实现**：`capture/print.html` 的 `body` 改为居中 flex（`align-items/justify-content: center`，`html,body{height:100%}`）；未加 `overflow:hidden`，以免在极端情况下静默裁切 —— 宁可退回分页也不丢内容。

**为何无需重启**：`print.html` 由主进程在每次导出时 `loadFile` 读取，改动即时生效；`pdf-export.js` 的修复属主进程代码，需重启（已执行）。

**源图自证**：把 PDF 内嵌的那张源图抽出解码后统计（`.tmp/pdf-source-image-FlateDecode-0.bin`，1440×2520 FlateDecode RGB），整幅列平均亮度 18–39、最右非白列在 99.9% 处 —— 证明**白块不是选区自带**，而是排版留白。
