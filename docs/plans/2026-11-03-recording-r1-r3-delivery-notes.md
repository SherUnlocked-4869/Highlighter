## 1. R0 基线实测记录（本会话环境）

R0 的“性能 A/B”部分需要在具备**真实屏幕采集能力**的桌面环境完成；本次开发主机不具备该能力，因此下面的记录是“能力与门禁基线”，不是方案 §6.2 要求的性能基线。所有未执行项在本文件 §6 明确列出。

### 1.1 主机能力（实测，2026-11-03）

| 项目 | 实测结果 |
|---|---|
| 显示器 | 仅 1 块：物理 2240×1400 @1.5x（DIP 1493×933），无副屏 |
| 桌面像素读取 | 可用（cua-driver 可截图；`desktopCapturer.getSources` 能返回屏幕源与缩略图） |
| Electron 屏幕视频采集 | **不可用**：`getDisplayMedia` 报 `Could not start video source`；Chromium 日志 `Cannot initialize any DxgiOutputDuplicator instance`（DXGI 桌面复制初始化失败）。追加测试 `--enable-features=AllowWgcScreenCapturer`、`AllowWgcZeroHz`、`--disable-gpu` 及组合，均失败 |
| 结论 | 本机无法验证“真实屏幕/系统音采集”；E2E 用主进程环境变量开启的**合成采集源**（`HIGHLIGHTER_E2E_FAKE_CAPTURE=1`，渲染层不可开启）覆盖其后的完整产品链路 |

## 2. 交付内容（R1–R3）

### R1 素材与恢复基础

- `recordings/` 持久数据根（非 cache），纳入数据目录迁移的复制、校验、回滚清理与写入协调。
- 录屏项目 `project.json`（schemaVersion 1）+ `capture.webm`；项目状态 `capturing → ready / recoverable`。
- 源会话服务扩展：项目目录直写、持久会话重挂载、`detachSession`、分片序号/重放/缺口、项目目录永不被会话清理删除。
- 断点检查点 + 启动惰性恢复：`capturing` 清单自动标记 `recoverable`（`interrupted`）；打开时探测，可用则纳入记录（`markReady`），不可用保留原文件并给出错误说明。
- 关闭编辑器/重录/重启不丢素材；删除项目清理项目原片，用户另存的成片不受影响；导出/编辑引用未释放时拒绝立即删除。

### R2 录前与录中体验

- 主窗口新增 `recording` 路由（录屏工作台）：区域/全屏两种模式、显式显示器目标（名称/ID/分辨率/主屏/已选择，多屏不静默回退）、系统声开关、麦克风开关+设备下拉（含“重新选择 / 不录此音源继续”预检）、帧率 30/60（高级保留 5/16/24）、画质三档、倒计时关/3s/5s、开始按钮、录制中横幅+回到录制、最近/全部记录。
- 录制控制条精简为：状态+计时 | 麦克风（仅实际采集时）| 暂停/继续 | 完成 | 更多（标注全套 + 音量 + 放弃本次）；计时剔除暂停；暂停有文字+颜色双提示；准备/倒计时/录制/暂停/整理/完成状态机；分片 ACK 失败或序号缺口自动暂停并明确报错，不伪装成功。
- 麦克风设备精确约束、运行中静音只作用于麦克风总线；画质映射码率；倒计时可配置。
- 重复入口仲裁：录制中再点入口只定位现有控制条，不新建采集、不清理当前录制；托盘与快捷键（打开工作台/区域/全屏/暂停继续/完成）统一走同一命令路径，状态推送丢失时可拉取恢复。
- 区域入口复用既有截图选区几何（专用精简选择器未单列，见 §6）。
- 设置页录制区收敛为“默认值 + 存储”，录制时参数就近放在工作台。

### R3 编辑与导出闭环

- 独立编辑器窗口（可缩放/最大化、frameless 自绘标题栏）：大预览、单轨双手柄时间线（拖动/键盘/精确时间输入、播放所选、恢复完整范围；播放头移动不改变裁剪点）、右侧导出参数（MP4/GIF、GIF 长边/帧率与预算、最终成片尺寸）、进度/取消/重试、结果条（打开/地址/目录）。
- 草稿自动保存（去抖 + revision CAS；冲突提示并重新载入；关闭前落盘）。
- 唯一“导出”入口：主进程持有保存对话框与目标冻结，复用既有导出任务服务（幂等/取消/校验/原子发布/回执），导出记录写回项目。
- 关闭窗口只关编辑器；从“最近记录/全部记录”可继续编辑；重启后项目与草稿仍在。
- 探测失败/恢复态：显示原因 + 重试 + 打开素材目录，不给假时长、不提供导出。

## 6. 未验证项与真机补测清单

## 7. R4 交付（第二轮：模式与剪辑增强）

上游 R4（方案 §7/§8.1/§8.2）。契约：[2026-11-03-recording-r4-contracts.md](2026-11-03-recording-r4-contracts.md)。

### 交付内容

1. **窗口录制**：真正的窗口视频源（`desktopCapturer types:['window']`），工作台第三张模式卡与窗口列表/刷新/空态/失败重试；主进程下发**不透明单次 token**（120s TTL、64 条上限、不下发 source id），录制窗绑定窗口源；冻结输出画布尺寸（录制中窗口缩放/移动按 contain 适配，不改变编码分辨率）；2s 源失效轮询 → `record:source-lost` 推送，渲染层结束并保留素材；窗口遮挡/最小化按视频轨 `mute` 尽力自动暂停 + 提示。窗口模式**不提供屏幕标注浮层**（坐标不可靠，见 §7 已知限制）；记录持久化为 `mode:'window'`，可按“窗口”筛选。
2. **多段裁剪**：`edit.keepRanges[]` 多段模型（沿用 schema v1：排序/不重叠/允许相接/最多 20 段/最短 100ms）；编辑器时间线按段渲染保留块与删除空档，支持在播放头拆分、删除当前段、恢复整段、撤销/重做（栈 50，Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y），播放自动跳过删除区间，统计显示“保留/原片”；草稿继续用 CAS 保存 keepRanges 数组。
3. **WebM 输出**：导出格式新增 `webm`；完整无编辑 + 源分辨率 + 源帧率时走流复制（`-c copy`，不重编码），存在裁剪/缩放/帧率/质量变化时以 VP9+Opus 重编码并严格符合编辑。
4. **导出分辨率/质量/帧率**：`video.resolution ∈ {source,1080p,720p,480p}`（目标长边上限 1920/1280/854，**绝不放大**，UI 只显示可用档位并展示最终宽×高）、`quality ∈ {standard,high,ultra}`（MP4 x264 CRF 28/23/18；WebM VP9 CRF 34/28/22）、`fps ∈ {source,30,60}`（高于源帧率被拒绝、UI 隐藏）；多段导出按“分段输入 → trim/atrim → 可选 fps/scale → concat”合成，时长校验按段数放宽容差。
5. **服务与外围**：导出临时文件按格式扩展名；发布校验使用新 expected（总时长/宽高/音轨）；导出结果服务与项目 schema 接受 `webm`；项目导出记录保存 format webm。

### R4 偏差与已知限制

1. 窗口模式无录中屏幕标注（坐标随窗口移动不可靠）；区域/全屏标注完整保留。
2. 窗口最小化/不可见检测依赖 Chromium 轨道 `mute`（尽力而为）；真实窗口采集、最小化/关闭/跨屏/遮挡行为需真机验证。
3. 空选择（删光所有段）无 schema 表示：当前会话禁止导出并提示，但草稿写 `keepRanges: []` 后重新打开会回到整段（已知限制）。
4. 导出分辨率/质量/帧率为会话内 UI 状态，不写入草稿（重开编辑器回默认 source/standard/source）。
5. 撤销历史仅会话内；多段仅支持源时间顺序保留，不支持重排/重复素材。
6. WebM 流复制路径无进度事件（纯 remux，进度停在 0 直到发布）；其余编码路径正常进度。
7. 本机仍无法验证真实屏幕/窗口采集（DXGI 桌面复制不可用），E2E 使用主进程合成采集源覆盖其后链路。

### 追加真机补测（在 §6 基础上）

7. 窗口录制：窗口遮挡/最小化/关闭/跨屏移动、目标窗口尺寸变化、系统声音与实际音轨一致性。
8. 多段拼接：A/V 同步、段边界首尾帧、暂停区间映射、30/60 FPS 源的分段导出。
9. WebM 成片在常见播放器/剪辑软件的兼容性；GIF 预算与多段组合。
