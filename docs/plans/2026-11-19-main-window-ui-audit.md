# Highlighter 主窗口全页 UI 走查与改造方案

日期：2026-11-19 · 状态：14 个主窗口入口已迁移，见文末实施验证。

## 结论

保留现有暖色主题、导航分组和页面信息架构，做一套**紧凑但不等高、低噪但不藏常用操作**的桌面控件系统。上一轮通用按钮已设 30 CSS px 下限；继续统一缩尺寸既不会解决伸展、溢出和错位，也会把录制模式、模型预设等带说明的选择卡误当成普通按钮。

先修两个已复现的问题：截图历史的「加载更多」在无下一页时仍显示，以及用量页的「清除数据」在放大窄窗里被挤出。再以 AI 对话、截图历史、AI 与模型为共享组件样板，最后迁移其余入口。不要为引入新特性而重写 UI 或改变存储、IPC 和默认行为。

## 范围与证据

- 范围是 `config/config.html` 左侧的全部 **14 个主窗口入口**及代表性子状态。独立截图编辑器、钉图、搜索弹窗、剪贴板面板、划词浮条、录制控制条和录屏编辑器不在本轮。
- 在 Windows 副屏用实际 Electron 43.8.3 / Chromium 150.0.7871.250 走查，使用隔离测试数据根。共记录 66 个状态观测（52 张截图）：中文深色约 1120×820、英文浅色紧凑约 882×720，并在后一尺寸做 125% 页面放大（约 705×576 CSS 视口）；副屏系统缩放另为 125%。
- 覆盖：首页六个分组、截图与录制设置三个页签、模型三个页签及展开/添加弹窗、历史有数据/选中/无结果、录屏全屏/区域/窗口模式、用量授权前/夹具数据/展开数据源，以及多处长页底部。历史图片和用量数据为夹具；Everything 为模拟后端。此次未操作真实录制、外部 AI、删除或迁移，也不是完整无障碍或性能验收。

## 逐页处理

| 页面 | 当前观察 | 推荐设计 |
| --- | --- | --- |
| 快捷功能 | 大面积可点击行与快捷键胶囊并存；行只有鼠标点击路径，描述和按键挤在同一行。 | 分开「运行」与「改快捷键」两个真按钮，不嵌套；改键保留键帽外观。宽时对齐名称、描述和按键，窄时描述移到下一行。六个分组可换行，不藏常用入口。 |
| 翻译 | 按钮尺寸正常；宽窗左右两个大面板，最小窗变为上下，结果和复制按钮容易落到首屏之外。 | 维持一个主按钮「翻译」，「清空」降为轻操作，「复制结果」跟随输出。按实际内容区宽度决定并排还是堆叠，不按外窗一刀切。 |
| AI 对话 | 「发送」实测约 60–61 px，原因是 flex 同行默认拉伸，并非通用按钮最小高度。 | 单独对齐发送键，输入框固定宽、限高随内容增长；保留 Ctrl+Enter 与换行，验证中文输入法、发送后焦点和等待态。 |
| 截图历史 | 无结果与只有三条数据时仍显示「加载更多」，实测 `hidden=true` 但计算样式仍为 flex；未选时也出现一整条禁用的批量工具栏。卡片选中后显示多达五个并排操作。 | 先修隐藏属性被显示声明覆盖；保留选择入口，选中后才展开批量动作。卡片常用动作直出，其余放「更多」；清理无效项与清空全部分层，不把清空做成常驻主按钮。保留长截图不可编辑的提示。 |
| 录屏 | 模式卡实测约 85–104 px，包含不同模式的说明，和普通按钮不是同一类。开始按钮另有 170 px 最小宽度。 | 保留三张选择卡并降低边框/阴影权重；内容窄时改为带描述的选项行。开始录制仍是主操作，按模式保持明确文案。录制中的停止、错误和目标选择不可收进「更多」。 |
| 划词工具 | 排序行约 68 px，单行截断说明，右侧又有开关、上移和下移；长页最后才有保存。 | 统一 32 px 排序命中区和轻量图标；窄时描述换行保留。拖放与键盘按钮都保留，移动后恢复到对应行的操作焦点；新增与保存分组。 |
| 本地搜索 | 分类区已使用容器查询和 subgrid，名称/规则/删除列对齐，已有清楚的保存层级。上方常规设置仍沿用旧表单。 | 把现有分类区作为列表样板；只对齐新表单、操作栏和焦点规范。保存分类仍是显式提交，恢复默认仍保留原有持久化时机；不要改动草稿生命周期。 |
| 剪贴板历史 | 状态设置用原生复选框，与其他页开关视觉不一致；保存、打开面板、刷新和两种清空分布在两块。 | 显式保存与打开面板分开；开关外观可统一，但保留现有草稿/提交语义。清空普通、清空含置顶分级并保留确认，未启用时说明不可用原因。 |
| 用量 | 不少图表、分段、表头按钮短于 24 CSS px（需按实际命中与间距逐项判断）；125% 窄窗展开数据源，英文清除数据超右边 5 CSS px。 | 覆盖信息与清除操作拆成可换行组；保留时间范围、刷新和筛选在易发现的位置。扩大有效点击区而不必放大文字；数据表内部可滚动，不能把整页撑宽。 |
| 通用 | 大量固定 60 px 表单行；即时生效的外观设置和软件更新卡是两种流程。 | 统一短行和说明行两档；设置继续即时生效，不造全页保存。更新卡内只强调当前有效的下载/安装动作，其余采用辅助样式并在窄宽换行。 |
| 截图与录制 | 页签样式单独定义；路径行把说明、固定宽输入框和「选择」挤在一排。 | 共用页签和表单布局；路径字段和选择按钮成组，窄时移到说明下方。维持截图输出、OCR、录制三个子页与已有设备选择行为。 |
| AI 与模型 | 「添加供应商」「保存供应商配置」同时是高亮；另有配置文件、Coding Plan、展开编辑、模型目录、连接测试与删除。 | 列表态突出「添加」，有手动保存的编辑态突出「保存」，次要入口归组。供应商行保留状态/展开语义。添加供应商和导入模型作为原生对话框候选，不动连接及凭据逻辑。 |
| 系统与数据 | 路径、代理、诊断和重置操作密度差别大，底部「恢复默认设置」单独悬在卡片外。 | 分成数据位置、代理、本地诊断和危险操作；路径组窄时下移。清理与重置区明确影响范围，维持确认、导出字段和迁移机制。 |
| 关于 | 两个普通按钮已经不大，但分散在两行，视觉上不成组。 | 保持轻量：版本与状态集中，项目主页用可识别外链样式，软件更新作次要跳转；不加主按钮或新面板。 |

## 统一设计规则

- **尺寸按角色，不按标签。** 建议普通文本按钮 30–32 CSS px、表单输入和选择 32–36 px、图标操作目标 30–32 px（图标 14–16 px）、窄密度导航约 36–40 px；支持较大触控目标。设置行建议单行约 44–48 px，有说明自然增高；选择卡按内容决定高度。24×24 CSS px 是 [WCAG 2.2 目标尺寸下限规则](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)，不是要求统一缩到 24 px；标准另有间距等例外。
- **每个任务区只强调当前主操作。** 保存、开始、发送用强调色；添加、打开等按当前任务分为主或次；刷新、清空输入、恢复默认等按风险和频率处理。破坏操作独立、文案明确，颜色不是唯一提示；等待、不可用、未修改是不同状态。
- **响应的是面板，不是屏幕。** 保留现有桌面窗口约束，底部操作组先换行再增加「更多」，不因缩窄而隐藏保存与高频操作。DOM 顺序与视觉顺序一致；不靠纯 hover 才能找得到关键动作。
- **区分即时保存和草稿。** 即时设置不新增保存；草稿页按原契约提交。原有 dirty、切页、大量项目分页、滚动位置、焦点恢复、危险确认及系统主题/主色/自定义 CSS 都是回归项。
- **共享基础，保留页面例外。** 复用按钮、页签、表单行、操作栏、空态和弹层的基础契约；大卡片、录制中控制、可滚动数据表仍独立。导航、表单和按钮使用同一密度体系，但不强制同高。

## Modern Web Guidance：采用什么，不采用什么

实际调用 [Google Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance-src) 的 `1.0.1` CLI 执行 `search` / `retrieve`，参考了 `design-token-reactivity`、`size-aware-styling`、`toolbar`、`declarative-dialog-popover-control`、`viewport-aware-dropdowns`、`form-fields-automatically-fit-contents`、`ime-safe-enter-submit`。它提供可检索的实现指南，不是生成视觉稿或自动修改页面的库。

| 机制 | 决策 |
| --- | --- |
| `@container` 尺寸查询 + `subgrid` | **首选。** 复用本地搜索和用量的模式，扩到翻译面板、表单和操作栏。子网格只用在真正需要跨行对齐的区域。默认样式能正常换行/堆叠。不用 resize 监听器反复算布局。 |
| CSS 自定义属性 + 样式查询 | **变量先行。** 复用现有 `body.compact` 下发尺寸和间距。只有组件在局部上下文确实要切换结构时再考虑 `@container style()`；用一个变量能解决的不要再写一层查询。 |
| `field-sizing: content` | **小范围采用。** 用于对话输入，固定可用列宽和最小/最大高度，超出内部滚动；不全局启用到目录、模型名或规则字段。 |
| 原生 `popover` + CSS Anchor Positioning | **小范围试点。** 优先用于历史卡和 AI 模型的低频操作组；弹层随触发按钮并在边缘翻转。先用可 Tab 的普通按钮组，不冒充 ARIA 菜单。验证 Escape、外点、关闭后归焦和窄窗，再扩展。参见 [Chrome Anchor Positioning](https://developer.chrome.com/docs/css-ui/anchor-positioning-api)。 |
| 原生 `<dialog>` + `commandfor` | **第二阶段试点。** 选一个现有模型弹窗验证模态焦点、Esc、返回触发器和切页关闭。声明式命令只负责显示/关闭，业务、权限及异步失败继续走现有处理器；不直接替换原生系统确认框。 |
| `@scope`、`focusgroup`、`interestfor` | **不进入首批。** `@scope` 可在新样式有复用价值时局部试验，避免改变现有自定义 CSS 的覆盖关系。运行时暴露后两者接口，但实际键盘及辅助技术行为尚未验证；不为几个按钮引入 polyfill。也暂不加跨页 View Transitions。 |

实际 Electron 运行时通过计算样式确认尺寸查询、样式查询与 `@scope` 生效；`subgrid`、表单自适应、锚点定位通过 CSS 支持探测；`popover`、`commandfor` 和 `showModal` 的接口存在。**接口存在不等于交互已经验收。** 当前是固定 Chromium 的本地桌面程序，首批不增加运行时依赖或 CDN。版本可对照 [Electron 43.8.3 发布页](https://releases.electronjs.org/release/v43.8.3)。

## 实施顺序与验收

| 批次 | 交付 | 可以继续的条件 |
| --- | --- | --- |
| 1. 基础与缺陷 | 锁定通用控件规格和 `[hidden]` 行为；修历史无下一页和用量窄窗；完成 AI 对话、截图历史、模型三页样板。 | 「加载更多」只在有下一页时显示且可 Tab；数据源清除操作不被裁切；发送键不会随多行输入长高；编辑态与非编辑态主操作明确。 |
| 2. 全入口迁移 | 剩余 11 个入口按样板迁移，共用页签、表单、导航密度；挑一个菜单、一个模型弹窗做原生交互试点。 | 14 个入口及子页在深浅色、中英繁三语、默认/紧凑、最小窗/常规窗、100%/125% 页面放大均可操作；允许数据表局部滚动，不允许整页横溢或可见控件被裁切。 |
| 3. 行为与资源回归 | 复用 Electron E2E 扩充焦点、可达性和状态用例；副屏对照图与实际输入法/高对比度/触控检查。 | Tab/Shift+Tab、Enter、Esc、焦点返回与禁用状态正确；删除/清空无误触或绕过确认；保存、录制、用量、模型与剪贴板契约不变。无新常驻定时器、监听器或浏览器窗口；比较同一组路由切换的 p50/p95 和空闲内存，不声称未测得的收益。 |

停止条件：出现数据契约变化、保存状态丢失、键盘不可达、原生弹层焦点错位或持续性资源回归，则停在该批次，不推广组件。

## 实施验证

- 统一了 14 个入口的按钮、页签、表单行、导航和操作区密度，保留原配色、即时保存与显式保存的区别。翻译、录屏模式、自适应表单按内容区宽度重排。
- 修复历史无下一页时的错误入口、用量数据源展开后的窄窗裁切和聊天发送按钮被拉伸的问题。历史卡原生 Popover 仍保留编辑、复制、打开、地址和删除；模型新增供应商使用原生模态对话框。未引入运行时依赖。
- 副屏 Electron：主窗口、本地搜索及新增 UI 回归共 15 项通过；扩展子页覆盖后新增 UI 用例 6 项复跑通过。分别检查中英繁、深浅色、两档密度、最小尺寸及 125% 页面缩放。搜索使用模拟 Everything、聊天使用本地回包夹具；未验证真实供应商、物理触控或真实输入法，仅在测试中模拟输入法组合事件。
- `npm run check` 和 246 项相关 Node 测试通过；未运行整个 `npm test` 或真实录屏、打包验收，也未把本地通过当作 CI 通过。
- 更新后原始截图和深浅两组总览：`test-results/main-window-ui/`。
- **资源抽样**：同一副屏交替对比基线 `605b05a` 和当前工作树。每次热切换 12 个入口、采样 96 次，记录从导航调用到第二个渲染帧的时间（不是异步数据加载完成时间）；回首页后等待 6 秒，再采样 Electron 进程私有内存。两轮基线切页 p50 为 20.5–20.9 ms、p95 为 29.0–29.3 ms；当前为 19.3–21.0 ms、28.2–29.5 ms。进程数量均为 5；短时空闲私有内存由 248.2–250.0 MiB 升至 252.8–255.9 MiB。同机两轮都测到小幅上升，未做长时间或多机确认，不视为泄漏，也不宣称资源无回归；如推进发布，需先在长时间空闲和重复切页场景复核。原始数据：`test-results/main-window-ui-comparison-idle.json`。
