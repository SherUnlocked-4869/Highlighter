## 7. Electron 兼容面清单

### 主进程 API

| 能力 | 当前用途 | 33→43 风险重点 |
|---|---|---|
| `app` | 生命周期、single instance、路径、版本、自启动 | ready 前路径设置、relaunch、portable wrapper |
| `BrowserWindow` / `webContents` | 主窗、工具栏、截图、长截图、贴图、识别、录屏 | sandbox、preload、透明/置顶窗口、process gone |
| `desktopCapturer` / `screen` | 屏幕、窗口、DPI、选区和录屏源 | source/display id、混合 DPI、权限与尺寸 |
| `ipcMain` | 约 94 个 handle/on 注册点 | sender/owner 校验、参数 clone 行为 |
| `safeStorage` | DeepSeek API Key | 加密后端、升级后解密兼容 |
| `globalShortcut` | 全局快捷键 | accelerator 兼容、冲突和退出清理 |
| `powerMonitor` | 睡眠/唤醒与划词 hook 恢复 | 事件顺序和重复恢复 |
| `clipboard` / `nativeImage` | 图片与文字复制、历史缩略图 | PNG Buffer 和 DPI |
| `dialog` / `shell` | 选择目录、保存和外链 | modal owner、URL allowlist、签名更新 UX |
| `Tray` / `Menu` | 后台运行与入口 | 图标、重建、退出时清理 |

### Renderer / preload API

| 能力 | 当前用途 | 33→43 风险重点 |
|---|---|---|
| `contextBridge` / `ipcRenderer` | 页面能力桥接 | sandbox preload 可用模块、最小暴露面 |
| `navigator.mediaDevices` | desktop stream | source constraint、权限和 MediaRecorder |
| `MediaRecorder` / Canvas capture | 静音 WebM 录制 | codec 支持、帧率、后台节流 |
| `showdown` in preload | AI Markdown | sandbox 不兼容，应迁出并清洗 HTML |

### 原生/外部进程

| 组件 | 连接方式 | 风险重点 |
|---|---|---|
| `selection-hook` | Node-API addon | Electron 内置 Node 24、睡眠恢复 |
| `sharp` | Node-API addon | win32-x64 预编译包、ASAR unpack |
| OCR sidecar | Rust child process + ONNX DLL | 路径、DLL 加载、模型校验、退出 |
| SmartSelect | C# child process | UI Automation、DPI 和生命周期 |
| FFmpeg | child process | unpack 路径、签名产物、转码退出 |
| `screenshot-desktop` | Windows helper | display 枚举、权限和路径 |

### 9.1 运行时与自动化结果

2026-07-29 在同一台 Windows 11 混合 DPI 双屏机器上完成：

| 项目 | Electron 43 结果 |
|---|---|
| Electron | 43.2.0，精确锁定 |
| Chromium / Electron Node / V8 | 150.0.7871.129 / 24.18.0 / 15.0.1240245-electron.0 |
| `npm run check` | 97 个 JavaScript 文件语法通过 |
| `npm test` | 245 passed，0 failed |
| `npm run check:version` | 通过 |
| 严格 runtime probe | `selection-hook`、`sharp`、SmartSelect、OCR sidecar、ONNX Runtime、OCR 模型和 FFmpeg 全部通过 |

`postinstall` 现在显式执行 `install-electron --no`。Electron 43 的 npm 包本身不再提供旧式
postinstall 下载脚本，因此仅执行 `npm ci` 而没有根项目 postinstall 会得到缺少
`dist/electron.exe` 的不完整安装。

safeStorage 的加密、不可用、清除和损坏密文路径均由自动化测试覆盖；开发版与打包版均能读取现有
配置和历史，日志未出现凭据解密失败。

### 9.2 Windows UI 与原生组件

开发版和 `win-unpacked` 均完成以下验证：

| 场景 | 结果 |
|---|---|
| 主窗口、快捷功能、About、系统设置 | 通过 |
| 已有截图历史加载 | 通过 |
| `selection-hook` 启动 | 通过 |
| OCR sidecar 热启动与模型加载 | 通过；打包版本次为 177 ms |
| 区域截图覆盖层 | 通过；混合 DPI 主屏尺寸与选区一致 |
| Esc 退出截图且不新增历史 | 通过 |
| 打包版 FFmpeg 生成 H.264 fast-start MP4 | 通过 |

Electron 43 首次 UI 冒烟发现截图窗口持续触发 8 秒 render timeout。诊断显示
`display.bounds` 为 2560×1440，但 `BrowserWindow.setFullScreen(true)` 最终产生
2572×1446 的 content bounds。renderer 的尺寸保护因此正确拒绝展示错误尺寸的覆盖层。

修复包含两部分：

- 截图初始化改为 renderer-ready 握手，消除截图数据与 renderer listener 的竞态。
- Windows 截图覆盖层使用无边框、`screen-saver` 级 always-on-top 窗口和精确 display bounds，
  不再调用会增加不可见边框补偿的 fullscreen 状态。

修复后开发版与打包版覆盖层均立即显示，尺寸为 2560×1440，并能安全退出。

### 9.3 打包验证

为了不覆盖 2.0 基线，Electron 43 产物生成在临时隔离目录：

| 产物 | MiB | 相对 2.0 基线 |
|---|---:|---:|
| NSIS installer | 144.54 | +14.7% |
| portable | 144.28 | +24.0% |

体积增长主要来自 Electron 43/Chromium 150 运行时。两个产物均未签名，符合签名工作尚未进入
Task 6 的现状。

默认 ASAR integrity 构建在向 `Highlighter.exe` 写入 `ELECTRONASAR` resource 时连续两次收到
Windows `UNKNOWN: unknown error, open`。在不修改仓库配置的情况下，用
`disableAsarIntegrity=true` 完成了本轮兼容性打包与 `win-unpacked` 冒烟。发布构建不能使用该
绕过；Task 3 必须在启用 fuses 前解决此写入问题并恢复严格 integrity 验证。

### 9.4 性能对比

在主窗口隐藏、5 个应用进程保留的暖态快照：

| 指标 | Electron 33 | Electron 43 | 变化 |
|---|---:|---:|---:|
| Working Set | 495.7 MiB | 460.2 MiB | -7.2% |
| Private Memory | 404.4 MiB | 450.5 MiB | +11.4% |

Electron 43 的实际驻留 Working Set 没有回退；Private Memory 超过 10% 阈值，表现为
Chromium 150 进程提交/保留地址空间增加，而非同幅度的驻留内存增长。当前解释可接受用于继续
兼容工作，但 release matrix 仍应在冷启动与三次重复测量后决定是否设为正式预算。

本次 Electron 43 OCR 热启动为 177–230 ms，处于 2.0 历史记录 156–227 ms 的同一波动区间。
没有足够稳定的冷启动和首次截图计时数据，因此暂不宣称这两项性能通过。
