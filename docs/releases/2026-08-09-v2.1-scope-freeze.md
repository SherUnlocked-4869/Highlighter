# Highlighter 2.1 范围冻结与候选基线

- **冻结日期：** 2026-08-09
- **冻结提交：** `1a57468188cbbeac949034462512ca10e9062577`
- **开发版本：** `2.1.0-beta.0`
- **目标平台：** Windows 10/11 x64
- **发布形态：** NSIS 安装版与 portable 便携版

`2.1.0-beta.0` 是内部稳定化版本标识，不代表已经发布公开 Beta。公开 Beta 必须满足本文门禁并使用新的版本提交。

## 1. 产品定位

2.1 将 Highlighter 收敛为 Windows 本地优先的截图、OCR、划词与 AI 后处理工具。本阶段不继续扩大功能面，优先完成可信发布、安全边界、诊断和真实环境验证。

## 2. 冻结范围

2.1 只接受以下工作：

- 修复冻结基线上能够复现的正确性、稳定性、性能或兼容性问题。
- 完善版本、CI、签名、Release、安装和回滚门禁。
- 收口 preload、CSP、导航、新窗口、IPC sender/owner 和生产包完整性边界。
- 增加本地诊断、异常退出记录和脱敏验证。
- 为降低回归风险而进行的等价模块拆分；重构提交不得混入产品行为变化。
- 补齐真实 Electron renderer、NSIS/portable 和 Windows 硬件验收。

2.1 不接受以下工作：

- 新增截图、标注、OCR、长截图、贴图或录屏功能。
- 新增 AI 动作、模型能力、服务商或提示词功能。
- 录屏音频、跨平台、云同步、团队协作或插件市场。
- 不服务于上述门禁的大规模 UI 改版或数据格式迁移。

OCR 历史全文搜索、剪贴板兼容模式和 AI 服务商抽象保留为 2.1 稳定发布后的候选项，必须分别评审和提交。

## 5. 2.1 发布门禁

- [ ] PR CI 执行语法、Node 测试、长截图、版本一致性和 Electron runtime probe。
- [ ] 生产 Release 强制签名，并验证发布者、时间戳、SHA-256、fuses 和 ASAR integrity。
- [ ] 真实 renderer smoke 捕获 console error、pageerror 和 render-process-gone。
- [ ] 所有窗口有统一安全选项、导航/新窗口守卫和最小 preload。
- [ ] 全部 IPC 完成 sender 与窗口 owner 审计。
- [ ] 可导出默认离线且经过 canary secret 扫描的诊断包。
- [ ] NSIS 与 portable 均完成打包、启动和退出烟测。
- [ ] 从 2.0.0 覆盖安装后配置、历史、API Key 和数据目录保持不变。
- [ ] Windows 10/11、100%/125%/150%/200% DPI、混合 DPI 多屏、睡眠恢复和 RDP 完成验收。
- [ ] 公开 Beta 与正式版本使用独立版本提交、匹配的 `v*` tag 和不可覆盖的 Release 资产。

## 6. 变更与提交纪律

- 每个路线目标使用独立提交；安全、重构、发布和功能工作不得混在同一提交。
- 任一范围变更先修改本文并单独提交，说明用户价值、风险、验证方法和延期代价。
- 构建产物不进入源码提交；Release 资产由受保护的发布流程生成。
- 任何门禁失败都保留当前可运行版本，不通过重写远端历史隐藏失败。
