### 8.1 第二个卡点：旧版卸载器"自我误判"（13:43 定位，含兼容垫片）

新检查**已在真实安装器里执行并通过**（用户 13:42 那次安装留下了 `$PLUGINSDIR\ccar.ps1` 与 `ccar.out`，内容 `none`），但安装仍停在**同一句**「Highlighter 无法关闭」。把进度窗口的控件文本读出来才确认：那是 **`uninstallOldVersion` 的失败提示**（`installUtil.nsh:219`，与运行检查共用同一句 `$(appCannotBeClosed)` 文案）：

1. `installSection.nsh:52` 调 `uninstallOldVersion`，把**上一版（2.3.1）自带卸载器**以 `ExecWait ... _?=$installationDir` **原地**运行；
2. 2.3.1 的卸载器内置**旧判据**（路径前缀），而**它自己就跑在安装目录里** → 永远匹配自己、永远无法结束自己 → 重试 5 次后弹框。**与用户是否开着应用无关**。
3. 本环境叠加：安装器进程的 `$PLUGINSDIR` 落在 `%LOCALAPPDATA%\Temp\**Low**`（低完整性/受限上下文），让"删除 `Program Files` 下的旧安装"更易失败。

**垫片**：`customInit` 在安装前删除旧版卸载入口（HKCU/HKLM × 两个键变体），使 `uninstallOldVersion` 读到空 `UninstallString` 后立即返回，改为**原地覆盖安装**；新安装包随后写入自己的卸载入口。

**代价与推荐路径（采纳旁路观察者意见）**：垫片**不清理旧版残留文件**。因此**推荐先在「设置 → 应用 → Highlighter」正常卸载 2.3.1，再运行新安装包**——该路径不传 `_?=`，卸载器会先把自身复制到临时目录，不会自我误判，结果是一次**干净安装**；垫片仅在用户无法正常卸载、或直接覆盖安装时兜底，并可在后续版本移除。

**可复现性注记**：13:27 这次重打包时 GitHub 已不可达（`connect ETIMEDOUT 20.205.243.166:443`），electron-builder 无法下载 Electron 运行时；改用 `--config.electronDist=<repo>/node_modules/electron/dist` 打包成功（日志 `using custom unpacked Electron distribution`）。**联网的 CI 环境不需要该参数。**

**用户升级时的已知陷阱（应写进发布说明）**：应用默认开机自启 + 托盘常驻，**关闭窗口不等于退出**（`main.js` 的 `window-all-closed` 是空实现）。升级前请从**托盘图标右键 → 退出**。
