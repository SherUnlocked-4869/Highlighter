# Highlighter 2.1 稳定发布版实施计划

**目标：** 将 Highlighter 从 Electron 33 迁移到受支持的 Electron 43，建立可信签名与可止损的更新发布链路，补齐真实 Electron 冒烟测试、本地诊断导出和关键安全边界。

**范围：** Windows 10/11 x64；NSIS 安装版与 portable 便携版。2.1 不新增截图、OCR、长截图或录屏业务功能。

**基线：**

- 当前版本：Highlighter 2.0.0、Electron 33.4.11、electron-builder 26.15.3。
- 当前 CI：Windows 上执行语法检查、238 项 Node 测试和 unsigned NSIS 构建。
- 当前安装包：约 126 MB；便携版约 116 MB。
- 当前已有：`contextIsolation: true`、`nodeIntegration: false`、日志脱敏与轮转、显示器诊断、渲染进程/子进程退出日志。
- 当前缺少：签名、更新客户端、发布通道、CSP、renderer sandbox、统一导航限制、打包产物冒烟测试、诊断包。
- 当前约有 94 个 `ipcMain.handle/on` 注册点；2.1 的 sender 审计必须覆盖完整 IPC 面，而不只覆盖新接口。

## 1. 发布原则和不可变约束

1. **功能冻结。** 2.1 只解决运行时、发布、诊断、安全和验证问题。
2. **数据兼容优先。** 不改变现有配置结构、数据目录定位器、截图历史格式或迁移语义。
3. **升级失败不得损坏用户数据。** 二进制升级与数据迁移解耦；2.1 不引入不可逆的数据 schema 迁移。
4. **生产包必须签名。** Release workflow 未获得有效签名时直接失败，不能静默降级为 unsigned。
5. **更新不打断任务。** 截图、OCR、长截图、录屏或数据目录迁移进行中时，不允许调用 `quitAndInstall`。
6. **更新默认由用户确认。** 后台只检查；下载和重启安装均由用户明确触发。
7. **portable 不原地自动更新。** 便携版仅提示新版本并打开 Release 页面；自动安装只支持 NSIS。
8. **2.1.0 是更新能力的引导版本。** 2.0.x 没有 updater，用户必须手动安装 2.1.0。正式验收的自动更新路径是 2.1.0 → 2.1.1。
9. **诊断默认本地。** 不自动上传崩溃、日志、截图、提示词、API Key 或路径信息。

## 2. 推荐架构

### 2.1 运行时升级

- 将 Electron 精确锁定到 `43.2.0`，避免 release 构建因 caret 范围获得未验证版本。
- Electron 每月由 Dependabot 提交 patch/minor 更新；每个新 major 单独建兼容任务。
- `selection-hook`、`sharp` 和 `onnxruntime-node` 均基于 Node-API，理论上不依赖 Electron ABI，但仍必须在打包后的 Electron 43 进程中实际加载验证。
- Rust OCR sidecar、C# SmartSelect 和 `screenshot-desktop` 不直接链接 Electron ABI，验证重点是进程启动、路径解析、权限和 DPI 行为。

### 2.2 更新与发布

- 使用 `electron-updater` 的 NSIS updater。
- 使用公开 GitHub Releases 作为更新源：
  - stable：`v2.1.0`、`latest.yml`
  - beta：`v2.1.0-beta.1`、beta channel manifest
- stable 用户默认不接收 prerelease；测试通道必须由设置页显式开启。
- `UpdateService` 是独立服务，封装 updater 事件、状态机、节流、错误归一化和安装门禁；renderer 不直接接触 `autoUpdater`。
- 生产 Release 使用受保护的 GitHub Environment，在人工批准后签名、验证并创建 draft release；人工确认后再发布。

### 2.3 签名

默认选择 **Azure Trusted Signing**，原因是适合 CI、无需上传 PFX、可即时建立发布者信任。若账号或地区资格不满足，回退到可导出的 OV Authenticode 证书。

密钥只存在于 GitHub Environment secrets：

- Azure：`AZURE_TENANT_ID`、`AZURE_CLIENT_ID`、`AZURE_CLIENT_SECRET`
- OV 回退：`WIN_CSC_LINK`、`WIN_CSC_KEY_PASSWORD`

仓库只保存非敏感的 publisher、endpoint、account/profile 名称。release 配置启用 `forceCodeSigning: true`。

### 2.4 安全边界

- 所有 renderer 最终启用 `sandbox: true`。
- 把 `showdown` 从 preload 移出；AI Markdown 在 action renderer 中解析后必须经过 DOMPurify 白名单清洗。
- 为主窗口与 action 窗口使用不同 preload，避免 action 结果页继承设置、历史、凭据等不需要的 IPC 能力。
- 所有窗口统一安装：
  - `will-navigate` 拦截
  - `setWindowOpenHandler(() => ({ action: 'deny' }))`
  - 本地页面来源检查
  - 最小化权限请求策略
- 为每个本地 HTML 增加 CSP。允许项目实际需要的 `data:`/`blob:` 图片与媒体；禁止任意脚本、frame 和远程连接。
- IPC 注册层验证 sender URL 与允许页面；涉及窗口所有权的 IPC 继续验证具体 `webContents.id`。
- 生产包启用 Electron fuses：
  - `runAsNode: false`
  - `enableNodeOptionsEnvironmentVariable: false`
  - `enableNodeCliInspectArguments: false`
  - `enableEmbeddedAsarIntegrityValidation: true`
  - `onlyLoadAppFromAsar: true`
  - `grantFileProtocolExtraPrivileges: false`（兼容验证通过后启用）

### 2.5 诊断

增加本地 `DiagnosticsService`，一键生成 ZIP，默认包含：

- Highlighter、Electron、Chromium、Node 版本
- Windows 版本、架构、安装类型
- 显示器 bounds/workArea/scaleFactor 摘要
- OCR sidecar、SmartSelect、FFmpeg 存在性与版本/散列摘要
- 最近运行日志及轮转日志
- renderer/child process 最近异常退出记录
- 最近一次是否为异常退出
- 更新状态与最近一次更新错误

明确排除：

- API Key、Authorization、token
- AI 对话、划词内容、自定义提示词
- 截图、缩略图、录屏、OCR 结果
- 完整用户目录路径；统一替换为 `%DATA_ROOT%`、`%USERPROFILE%` 等占位符

ZIP 生成前再次运行递归脱敏器，并用测试中的 canary secret 证明产物不含敏感值。

## 8. 回滚策略

- Electron 升级、安全收口、updater、诊断分别独立提交，任一阶段可单独回退。
- 不在 2.1 引入不可逆数据迁移，因此回装 2.0 不需要降级 schema。
- Release 资产永不覆盖同版本文件；发现问题撤下 manifest，并发布更高 patch。
- 下载未完成或签名验证失败时保留当前版本，不调用安装。
- 安装前不删除录屏、OCR、长截图或历史数据。
- 2.1.0 发布后至少保留 2.0.0 安装包、2.1.0 安装包、SHA-256 和 release notes。
