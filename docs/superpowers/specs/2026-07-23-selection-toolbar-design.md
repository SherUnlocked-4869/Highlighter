# 可配置划词工具栏设计

## 目标

划词工具栏支持复制、搜索、翻译、解释以及用户自定义 AI 功能。用户可在独立的“划词工具”设置页面调整全部功能的显示状态和顺序，自定义翻译与解释提示词，并新增带有名称和提示词的 AI 功能。

## 配置模型

`selectionToolbar` 保存在现有 `electron-store` 设置对象中：

```js
selectionToolbar: {
  enabled: true,
  buttons: {
    copy: true,
    search: true,
    translate: true,
    explain: true
  },
  order: ['copy', 'search', 'translate', 'explain', 'custom:polish'],
  prompts: {
    translate: '翻译提示词',
    explain: '解释提示词'
  },
  customActions: [
    {
      id: 'polish',
      name: '优化',
      prompt: '优化这段话',
      enabled: true
    }
  ],
  searchEngine: 'bing'
}
```

主进程统一归一化配置：

- 旧版配置自动补齐顺序、默认提示词和空的自定义功能列表。
- 未知、重复或格式错误的自定义 ID 被丢弃。
- 功能名称最长 16 个字符，提示词最长 6000 个字符。
- 最多保留 12 个自定义功能。
- 顺序列表去重并移除不存在的动作，遗漏的有效动作自动追加。
- 未知搜索引擎回退到 Bing。

## 设置页面

页面包含：

- 划词工具栏总开关。
- “功能与顺序”列表，包含内置和自定义功能，可拖动或使用上下箭头排序。
- 每个功能的独立显示开关。
- 翻译与解释提示词编辑框。
- 搜索引擎选择。
- 自定义 AI 功能列表，可添加、编辑名称和提示词、启用/停用及删除。

排序、开关、添加和删除即时保存；文本编辑和搜索引擎通过“保存划词工具设置”提交。执行会导致页面重绘的操作先保存当前有效编辑内容，避免排序或新增功能时丢失尚未提交的文本。

## 工具栏行为

主进程收到划词文本后：

1. 读取并归一化最新设置。
2. 按 `order` 过滤出已启用功能。
3. 将动作解析为只包含 `id`、名称、图标和类型的安全描述。
4. 根据实际名称与数量计算工具栏宽度。
5. 向隔离的工具栏渲染进程发送划词文本和动作描述列表。

工具栏使用 DOM 文本属性渲染名称，不插入用户提供的 HTML。较长名称会获得更宽的按钮并在超出上限时显示省略号。

## 动作处理

- `copy`：写入系统剪贴板。
- `search`：使用已选择的 Bing、百度或 Google 模板构造 HTTPS URL，并交给默认浏览器。
- `translate`：将用户配置的翻译提示词作为 system 消息、划词内容作为 user 消息发送给 AI。
- `explain`：以相同方式使用解释提示词，并保留思考模式。
- 自定义功能：使用该功能的提示词作为 system 消息、划词内容作为 user 消息，并在结果窗口显示自定义名称。

渲染进程只能提交动作 ID。主进程重新读取当前配置，要求动作仍存在且可见，并从受信配置中解析提示词；渲染进程不能直接通过动作消息注入提示词。

## 错误处理

- 空文本、未知动作、已停用动作不执行。
- 没有 API Key 时，AI 功能跳转到功能设置。
- 翻译、解释及自定义功能的名称和提示词不能为空。
- 自定义功能数据经过长度、ID、数量和重复校验。
- 总开关关闭或没有可见功能时不显示工具栏。

## 测试与验收

自动化测试覆盖：

- 旧配置兼容与默认字段补齐。
- 自定义顺序对工具栏显示顺序的控制。
- 自定义功能启用、停用、无效数据过滤及动作解析。
- 翻译、解释和自定义提示词进入 system 消息，划词内容进入 user 消息。
- 主进程动作白名单与自定义结果窗口元数据。
- 设置页排序、提示词和自定义功能控件契约。
- 工具栏宽度、搜索 URL 与原有本地动作行为。

完成后运行 `npm run check` 和 `npm test`，并启动 Electron 检查设置页完整布局。
