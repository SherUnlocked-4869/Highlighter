# 划词工具栏长时间运行可靠性修复设计

## 问题

Highlighter 长时间运行或 Windows 休眠、锁屏后，划词工具栏可能不再出现。当前实现存在两条静默失效路径：

1. `selection-hook` 使用 Windows 低级鼠标和键盘钩子。系统可以静默移除失去响应的低级钩子，但库的 `isRunning()` 只反映 JavaScript 内部状态。应用没有监听休眠、恢复、锁屏或解锁事件，也没有重建钩子。
2. AI 工具栏动作通过全局 `isProcessing` 阻止新的划词事件。流式请求收到首个片段后，渲染进程会清除初始超时；如果连接随后永久停滞，主进程没有超时或中止机制，`isProcessing` 将一直保持为 `true`。

## 目标

- 休眠、恢复、锁屏和解锁不会让划词能力永久失效。
- 重复的系统恢复事件只触发一次钩子重建。
- 钩子启动暂时失败时进行有限重试，退出应用时不再启动新钩子。
- AI 流式请求在无数据、用户取消或窗口关闭后可靠释放全局处理状态。
- 旧结果窗口不能结束或取消新的流式请求。
- 生命周期行为可用不依赖 Electron 和原生模块的单元测试验证。

## 选择钩子生命周期

新增 `SelectionHookService`，由主进程注入钩子工厂、事件处理器、日志函数和计时器。

服务职责：

- 创建钩子并绑定 `text-selection`、鼠标、键盘、滚轮、错误和状态事件。
- 检查 `hook.start()` 的返回值；启动失败时清理半初始化实例。
- 在休眠或锁屏时取消待执行的重启并清理当前实例。
- 在恢复或解锁时先丢弃可能“假活”的旧实例，再延迟重建。
- 合并相邻的 `resume` 和 `unlock-screen` 事件。
- 启动失败后按固定间隔有限重试。
- `dispose()` 后清理钩子、计时器和监听器，且禁止后续重启。

主进程在 Electron ready 后注册 `powerMonitor`：

- `suspend`、`lock-screen`：调用 `suspend(reason)`。
- `resume`、`unlock-screen`：调用 `scheduleRestart(reason)`。
- `before-quit`：移除系统事件监听并 `dispose()`。

不使用周期性强制重启。周期性重启会在用户正在划词时丢事件；目前已确认的触发条件是系统电源和会话切换，事件驱动恢复更精确。

## AI 流式请求生命周期

主进程为每次工具栏 AI 请求创建独立控制器：

- `AbortController`
- 所属结果窗口
- 当前请求标识
- 滑动空闲计时器
- 取消原因

请求创建和每个流片段到达时重置空闲计时器。超过限制后中止网络请求、向仍存活的结果窗口报告超时，并在 `finally` 中释放 `isProcessing`。

取消、完成和窗口关闭均通过同一个幂等清理函数处理。IPC 处理器必须验证发送者属于当前控制器，避免旧的置顶窗口影响新请求。

渲染进程保留用户可见的超时提示，但改为滑动超时：每个数据或推理片段都会重新计时；超时时发送 `cancelStream()`，不再仅修改主进程布尔状态。

## 验证

- 单元测试覆盖启动去重、恢复事件合并、旧实例清理、失败重试和退出后不重启。
- 合同测试覆盖主进程电源事件接线、流控制器的中止/超时/来源校验。
- 运行 JavaScript 静态检查和完整测试套件。
